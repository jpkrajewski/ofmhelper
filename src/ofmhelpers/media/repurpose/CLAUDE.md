# repurpose

One video -> one repurposed copy, from JSON presets, plus a checker that measures how much a copy still matches its source. Exploring phase (2026-10-26): tests only where the user asked (`tests/unit/utils/test_capcut.py`, `tests/unit/iphones/test_recorder.py`, `test_matches_real_recording.py` run `apply_json_preset("capcut"/"iphone17")`).

## API (`repurpose.py`)
`Repurpose(src, dst, seed=7, recorded_at=when).apply_json_preset("hard").run()` (also `apply_video_preset(name, special=)`, `apply_audio_preset`, `apply_device_preset`, default device `strip`); `check(src, copy)` from `checker` -> `CheckReport`. A name is `presets/<name>.json` / `devices/<name>.json`, or any path to a `.json`. `*_special` knobs = Duplyfi, the former Special switch. Same seed = same copy.

## Layout
- `presets/` and `devices/` are JSON; new device/preset = a JSON file. The `capcut` device mirrors `media/capcut.py`'s 4K export (tags, Main L5.1, 28 Mb/s, no SEI, `encoder` renamed, empty compressorname); `iphone17` is a real iPhone 17 Pro Max recording by `ofmhelpers.media.recorder` (with knobs set they go into a `master` first, sized by `repurpose.master_for` to 1.5x the recorder frame and capped to the profile fps; 4K60 source on iphone17 / iphone16_usa, 6 s clip: 76 s -> 56 s / 118 s -> 80 s, same output size).
- `transformations/video.py`: filter order is in its docstring; `rotate` = a turn, a number or `[lo, hi]` drawn per copy, overscanned like the handheld; `rotate_both_ways` turns each copy left or right at random (off: always the drawn sign). `adjust.py`: CapCut's Adjust panel in slider units; calibrated: exposure, contrast, sharpen, particles; the rest first guesses, see its docstring.
- `extras/snapchat/` renders the caption bar as an RGBA PNG; its fractions were measured off a real snap, its height chosen (70% of the frame, user 2026-11-03).
- `pipelines/` — ready-made chains (a JSON preset + the code's fixed look) run as `python -m ofmhelpers.media.repurpose.pipelines.<name>`. `snapchat_iphone16_usa`: the knobs live in `snapchat_iphone16_usa.json` (2026-11-03, user "too dark, too zoomed": saturation +-1%, brightness 0..+0.01, gamma 1..1.01, which only ever draw up because the way to HLG and back takes 1% (the old brightness +-0.02 + gamma +-3% moved a copy from -7.5% to +5%, geometry off, against the source); corner zoom 0.2-0.5%, tilt +-0.05, drift 0.2-0.4%; CapCut `adjust.sharpen` 5, volume +-5%, pitch +-0.4 semitone, +-0.5 dB treble, no phaser/echo/chorus/compressor; the old stealth_wild-like mix measured luma -16%, saturation +14%, highlights clipped), the code pins mirror + 1-degree rotate + the snapchat caption (the turn is most of the zoom: a turned frame must be scaled up to still cover the output; picture cut away: 12% with the old 2 degrees and framing, 6.5% now), device `iphone16_usa` (recorder profile `iphone16_4k`: 2160x3840 HEVC Main 10 HLG, 24 Mb/s -- the POSTED reels are 4K CapCut exports, the 1080p `iphone16` profile threw 3/4 of the pixels away). Used by /trials (`ofmhelpers.features.trials`).
- `photos/` — stills of a video as a phone's own photos, from a JSON photo preset (`<name>.json`, `models.PhotoPreset`: device, pictures, lens, stills, retouch; a new target is a new file). `threads` = /threads (2026-11-17): 3 candidate stills per picture at jittered moments, PDQ-hashed, only ones > 64 bits apart kept (`distinct.pick`), each cropped (`retouch.crops` ladder) + toned + grained until > 64 bits from every sampled still (`distinct.changed`; the OOPSIE desktop spoofer's idea), JPEG with iPhone EXIF written by Pillow (`exif.py`: rationals as `IFDRational`, a float is written as a double and misread; GPSVersionID as bytes, a tuple keeps only its first number; no JFIF, no ffmpeg comment). Measured: PDQ moves with the crop only (2% a side ~30 bits, 4% ~55, 6% 60-100), tone + grain ~2.
- `checker/` — tier 1, the user's notes in `__init__.py` applied. Looks like source = any hash / SSCD puts >= 50% of the copy's frames on one line (`source_t = scale x copy_t + offset`, scale 0.8-1.25, Hough vote), or TMK matches. Frames: copy 1/s, source 10/s, picked on timestamps with `select` + `showinfo`. `sscd.py` and `tmk.py` are optional where installed (the lab pod, not the app image): SSCD via `OFM_SSCD_MODEL` TorchScript + torch, cosine >= 0.75, copy also mirrored; TMK+PDQF tools in `OFM_TMK_DIR`, commit 295fd16e, whole-video level 1/2 >= 0.7.
- `values.py` — knob values: number, `[lo, hi]` (uniform; symmetric ranges cover both directions), list of words (one picked), chance 0..1.

New knob = one field on `VideoSettings`/`AudioSettings`/`AdjustSettings` + its filter; new device/preset = a JSON file.

Why this setup (2026-11-20, owner "fast, iPhone, pass the self-check"): the `snapchat_iphone16_usa` pipeline it replaced made a near-lossless 4K60 master and a 10-bit HEVC recording per copy (~3 min a try on the owner's 4K60 CapCut export) with knobs too light to pass (PDQ/pHash/wHash/Chromaprint 100%, 3 of 3 tries failed). `spoof.json` = framing that moves the hashes (mirror on half the copies and a 1-3 degree turn left or right since 2026-11-20, owner: "it should mirror 50% of the time", "rotate between 1 and 3", "random direction too"; off-centre corner zoom 10-14 %, tilt, drift) + pitch +0.7-0.8 semitone, chorus, room echo (Chromaprint 0). `iphone16_h264` = an iPhone "Most Compatible" recording: one libx264 1080p30 encode (~42 s per 11 s 4K60 source), Apple make/model/software tags, Core Media handlers, moov last (no faststart); the same trade InstaLabs Spoofer calls its practical batch profile (OOPSIE writes H.264 720p with Core Media handlers but no Apple make/model). Measured on that source with mirror on every copy and a fixed 1 degree turn (before 2026-11-20): 6 of 6 copies passed, pHash 22-38, wHash 22-44, PDQ 0-11, Chromaprint 0. Colour, sharpen and grain do not move the checker (frames are grey, equalized and blurred before hashing): random mirror (50 %) + random turn +-1 degree + sharpen 0-10 + grain 1-3 passed 1 of 3 (smaller turns), fixed framing + sharpen/grain 2 of 3. Cards show the scores. ## Lab (`lab/`, 2026-10-26)
Which knobs / mixes hide a copy from the checker while it stays nearly identical. Never runs in the app; a big CPU box:
- `space.py`: every knob with its cap (the "nearly identical" limits: speed +-6%, zoom <= 6%, tilt <= 1 deg, pitch +-0.5 semitone...; mirror and black-and-white left out); random throws may go to 1.5x a cap.
- `measure.py`: VMAF against a reference with the copy's exact framing draws and none of its look (`VideoTransformer.from_draws`, same `-r` as the copy); TMK scaled so its 0.7 line sits at 50.
- `search.py`: calibration -> ablation -> random throws -> Optuna NSGA-II per part (video: least caught at VMAF >= baseline - 3, VMAF counted no higher than the baseline; audio: least Chromaprint % and least change); `--phases` runs a subset.
- VMAF baseline: an untouched strip copy scores 94.9 (the 720p CRF 23 encode alone); sharpening raises VMAF to 98 (VMAF's known enhancement gain), hence the cap. Floors and picks are relative to the baseline.
- RunPod run (what worked, 2026-10-26): REST v2 `POST https://api.runpod.io/v2/pods` with `cpu {id: cpu5c, vcpuCount: 32}`, image `python:3.12-slim` (same Debian / ffmpeg 7.1.5 as prod), `ports ["22/tcp"]`, `env.PUBLIC_KEY`, `entrypoint bash -c "apt-get install openssh-server ffmpeg g++ curl xz-utils; authorized_keys from $PUBLIC_KEY; exec sshd -D"`; SSH host/port from `GET /v2/pods/{id}` -> `ssh.direct` (no sftp: copy with `tar | ssh`). On the pod: uv, `UV_PROJECT_ENVIRONMENT=/lab/venv uv sync --frozen --no-dev --group lab --no-install-project`, `uv pip install torch --index-url https://download.pytorch.org/whl/cpu`, the SSCD model `https://dl.fbaipublicfiles.com/sscd-copy-detection/sscd_disc_mixup.torchscript.pt`, BtbN's static ffmpeg (has libvmaf) for `OFM_LAB_VMAF_FFMPEG`, the TMK tools built in python:3.12-slim (`OFM_TMK_DIR`), `PYTHONPATH=src`; long jobs under `nohup` (an idle SSH session was reset mid-run). cpu5c x 32 = $1.12/h; ~1.2 measurements/s on single knobs, ~0.6/s on mixes, with 20 workers. Delete the pod when done (`DELETE /v2/pods/{id}`).

Lab results 2026-10-26 (full write-up: `reports/lab/run-2026-10-26/FINDINGS.md`, local only): nothing passed every detector. Each falls to a different edit: PDQ/dHash to small framing, pHash/wHash partly to bigger framing (stealth_wild), SSCD only to the blurred-border look (2 of 16 copies), Chromaprint to pitch ~0.73 semitone + chorus + room echo (0% on 6 of 8 clips). The lab missed the last two: pitch was capped at 0.5 and VMAF scored the border as damage (it compares against the unbordered frame). Next: one preset stacking border + stealth_wild framing + pitch ~0.7 + chorus + room echo.

## Findings (2026-10-26, ffmpeg 7.1)
- ffmpeg's `vibrato` is nondeterministic in ffmpeg 8.0.1 (Windows, gyan full): the same chain flips between normal and a full-scale blowup (~30% of runs, any params; bisected 2026-10-30 by repeating identical commands). A blown chain measures like peak-normalized garbage and, after a ceiling limiter, can become a near-DC wall -- which plays as silence. Keep `vibrato` out of `loud` lists; the `snapchat_iphone16_usa` pipeline's audio self-check (`_verify_audio`) exists to catch any remaining source of this class.
- ffmpeg's `noise` seed is fixed by default: identical grain in every copy. Every copy here draws `all_seed`.
- Duplyfi's `aphaser` (in/out gain 0.4 x 0.74) costs ~10 dB, its chorus ~5 dB, `acompressor` at -30 dB ~11 dB: `match_level` measures copy vs source (same trimmed window) and adds it back before the limiter. Stereo reel: within 0.4 dB. A mono source comes out ~3 dB lower: `-ac 2` spreads it at -3 dB per channel (legacy uniqify too).
- `perspective` smears edge pixels instead of filling black; the handheld overscan keeps every edge out of frame.
- `unsharp` is positional `lx:ly:la:cx:cy:ca`; `5:5=0.2` is a parse error.
- Crop/scale round trips lose 1-6 px to even-rounding: the chain ends at the exact output size (numbers, not `iw`).
- ffmpeg 7.1 (Debian) has the `chromaprint` muxer: no fpcalc/pyacoustid needed. `pdqhash` 0.2.8 has no Linux wheel: the Dockerfile's build and test stages install `g++` to build it (runtime copies the compiled venv; libstdc++ is in slim).
- Frame sampling: ffmpeg's `fps` filter picks somewhere inside each slot, so a copy and its source sampled at different rates landed 0.1-0.4 s apart; a plain no-knob re-encode then read PDQ 34-104 bits and pHash 67% on fast handheld reels. Now: `select` on timestamps (first frame at/after each step) + `showinfo` times; the plain re-encode reads 100% on every method. Before the fix, a 0.1 s trim alone "beat" PDQ / dHash (0-17%): a sampling artefact, not a real weakness.
- Checker calibration (2026-10-26, scratchpad `calibrate.py` + `wcal.py`; source 10/s, copy 1/s): 16 unrelated reels, 236 ordered pairs, vs VID_6932 and 10 copies. Two template remakes left out as not unrelated: VID_7646 / VID_6738 and VID_7319 / VID_6932 (same spot, framing and sound, another girl; they match on several hashes and on Chromaprint). Per hash the highest threshold with no unrelated pair matching >= 50% in order, minus one step: PDQ 64 (clean to 91), pHash 12 (clean to 14, VID_3217<-1.mp4 at 16), dHash 6 (clean to 8, IMG_2967<-1.mp4 at 10), wHash 6 (clean to 7, VID_6683<-1.mp4 at 8). Copies caught at those: phash 12 finds low/medium/capcut/iphone17 >= 90%, hard 83%, extreme 67%, hard_sp 82%, extreme_sp 40%, hard_sp + iphone17 40%.
- SSCD / TMK false-positive check (lab pod, 8 test clips, 56 ordered pairs): SSCD median cosine at most 0.47 (threshold 0.75), 0 pairs matched; TMK min(level1, level2) at most 0.42 (threshold 0.7). TMK on a 6 s reel: plain re-encode 0.998, trim 0.3 s + crop 5% + saturation 0.963.
- PDQ is brittle to our handheld edits: `low` (tilt/shake/drift, pHash 5 bits) is ~52 bits on raw frames, 58 normalized; Meta's 31 catches only a plain re-encode (`iphone17`, 2 bits). pHash/dHash carry the verdict for light presets.
- Verdicts at those thresholds (copies of VID_6932): looks like source = low, medium, hard, extreme, low_sp, extreme_sp, iphone17; picture passes = hard_sp, capcut, hard_sp + iphone17. Sound matches on all but hard_sp + iphone17 (0.68). Old checker (pHash 10, any order, mirrors only) passed hard/extreme pictures: the new one is stricter.
- Audio as windows (16 items ~2 s, each may drift +-16 items off the track's best offset, >= 0.7 bits agree = found): 15 reels with sound, 210 ordered pairs: 0% everywhere except two pairs at 100% that really share a sound (VID_7646/VID_6738 0.94 whole-track, VID_7319/VID_6932 0.89). Copies of VID_6932: low/medium/hard/capcut/iphone17 100%, extreme 50%, low_sp 25%, hard_sp + iphone17 33%, hard_sp/extreme_sp 0%. Sounds like source = windows >= 50% (was whole-track >= 0.7).
- Cost: `check()` ~2-4 s per 12 s reel copy (hashing 16 query variants x 4 hashes per frame).
- Cost per copy, 12 s 1080x1920 reel: hard 8.9 s, hard+special 14.6 s, extreme+special 13.1 s, capcut (4K) 14.8 s.

- Duplyfi's phone imitation ("US Metadata": 24-model catalog with each phone's resolution/fps/bitrate, GPS in a US city, recent creation time, moov rewrite). Our `iphone17` device does the iPhone side more faithfully.
- TikFusion's hue rotation (`hue=h=` +-5..20 degrees).
- Checker: per-scene sampling, CLIP + faiss, an AugLy false-positive set (calibration used 16 own reels + 8 test clips); SSCD/TMK in the app image (torch ~1 GB).
