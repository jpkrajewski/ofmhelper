# repurpose

One video -> one repurposed copy, from JSON presets, plus a checker that measures how much a copy still matches its source. Exploring phase (2026-10-26): tests only where the user asked (`tests/unit/utils/test_capcut.py`, `tests/unit/iphones/test_recorder.py`, `test_matches_real_recording.py` run `apply_json_preset("capcut"/"iphone17")`).

## API (`repurpose.py`)
`Repurpose(src, dst, seed=7, recorded_at=when).apply_json_preset("hard").run()` (also `apply_video_preset(name, special=)`, `apply_audio_preset`, `apply_device_preset`, default device `strip`); `check(src, copy)` from `checker` -> `CheckReport`. A name is `presets/<name>.json` / `devices/<name>.json`, or any path to a `.json`. `*_special` knobs = Duplyfi, the former Special switch. Same seed = same copy.

## Layout
- `presets/` and `devices/` are JSON; new device/preset = a JSON file. The `capcut` device mirrors `media/capcut.py`'s 4K export (tags, Main L5.1, 28 Mb/s, no SEI, `encoder` renamed, empty compressorname); `iphone17` is a real iPhone 17 Pro Max recording by `ofmhelpers.media.recorder` (with knobs set they go into a `master` first, sized by `repurpose.master_for` to 1.5x the recorder frame and capped to the profile fps; 4K60 source on iphone17 / iphone16_usa, 6 s clip: 76 s -> 56 s / 118 s -> 80 s, same output size).
- `transformations/video.py`: filter order is in its docstring; `rotate` = a turn, a number or `[lo, hi]` drawn per copy, overscanned like the handheld; `rotate_both_ways` turns each copy left or right at random (off: always the drawn sign). `adjust.py`: CapCut's Adjust panel in slider units; calibrated: exposure, contrast, sharpen, particles; the rest first guesses, see its docstring.
- `extras/snapchat/` renders the caption bar as an RGBA PNG; its fractions were measured off a real snap, its height chosen (70% of the frame, user 2026-11-03).
- `pipelines/` — every repurpose run of the app (owner 2026-11-22). `pipeline.py` `Pipeline` drives `Repurpose`, fluent like it: `Pipeline.paths(src, dst).seed(7).load("spoof").run()` (or `.stage(preset, max_attempts=, tries_per_attempt=, strength_increase=, video=)`, `.return_on_unique()`, `.device()`, `.video()` in code). One JSON per run, `pipelines/<name>.json` = `models.PipelineSpec`: stages in order, each a preset with `max_attempts` x `tries_per_attempt` (strength 1 + `strength_increase` per failed attempt of that stage, via `Repurpose.stronger`, not called at 1), optional pinned `video` knobs; `device` for every stage; `return_on_unique` = the hash self-check decides, else the first copy whose audio passes is kept. Try n uses seed + n - 1. Every try: `verify_audio`, then `check(...).unique` when asked; a failed try logs why, each try is a Logfire span; no try passing deletes the copy and raises `StillLooksLikeSourceError`. `OFM_REPURPOSE_MAX_TRIES` (10) caps the combined `max_attempts` of any pipeline (refused before the first encode). Result: `models.RepurposeResult` (name, path, report, step, stage, attempts, strength, seconds), stored as is by /spoof. Runs: `spoof.json` (/spoof) and `snapchat_iphone16_usa.json` (/trials; checked 2026-11-22: same seed = same draws as the old hand-written chain, only the wall-clock creation time differs). `snapchat_iphone16_usa`: the knobs live in `presets/snapchat_iphone16_usa.json` (2026-11-03, user "too dark, too zoomed": saturation +-1%, brightness 0..+0.01, gamma 1..1.01, which only ever draw up because the way to HLG and back takes 1% (the old brightness +-0.02 + gamma +-3% moved a copy from -7.5% to +5%, geometry off, against the source); corner zoom 0.2-0.5%, tilt +-0.05, drift 0.2-0.4%; CapCut `adjust.sharpen` 5, volume +-5%, pitch +-0.4 semitone, +-0.5 dB treble, no phaser/echo/chorus/compressor; the old stealth_wild-like mix measured luma -16%, saturation +14%, highlights clipped), its pipeline stage pins mirror + 1-degree rotate and /trials passes the snapchat caption per run (the turn is most of the zoom: a turned frame must be scaled up to still cover the output; picture cut away: 12% with the old 2 degrees and framing, 6.5% now), device `iphone16_usa` (recorder profile `iphone16_4k`: 2160x3840 HEVC Main 10 HLG, 24 Mb/s -- the POSTED reels are 4K CapCut exports, the 1080p `iphone16` profile threw 3/4 of the pixels away). Used by /trials (`ofmhelpers.features.trials`).
- `photos/` — stills of a video as a phone's own photos, from a JSON photo preset (`<name>.json`, `models.PhotoPreset`: device, pictures, lens, stills, retouch; a new target is a new file). `threads` = /threads (2026-11-17): 3 candidate stills per picture at jittered moments, PDQ-hashed, only ones > 64 bits apart kept (`distinct.pick`), each cropped (`retouch.crops` ladder) + toned + grained until > 64 bits from every sampled still (`distinct.changed`; the OOPSIE desktop spoofer's idea), JPEG with iPhone EXIF written by Pillow (`exif.py`: rationals as `IFDRational`, a float is written as a double and misread; GPSVersionID as bytes, a tuple keeps only its first number; no JFIF, no ffmpeg comment). Measured: PDQ moves with the crop only (2% a side ~30 bits, 4% ~55, 6% 60-100), tone + grain ~2.
- `checker/` — tier 1, the user's notes in `__init__.py` applied. Looks like source = any hash / SSCD puts >= 50% of the copy's frames on one line (`source_t = scale x copy_t + offset`, scale 0.8-1.25, Hough vote), or TMK matches. Frames: copy 1/s, source 10/s, picked on timestamps with `select` + `showinfo`. `sscd.py` and `tmk.py` are optional where installed (the lab pod, not the app image): SSCD via `OFM_SSCD_MODEL` TorchScript + torch, cosine >= 0.75, copy also mirrored; TMK+PDQF tools in `OFM_TMK_DIR`, commit 295fd16e, whole-video level 1/2 >= 0.7.
- `values.py` — knob values: number, `[lo, hi]` (uniform; symmetric ranges cover both directions), list of words (one picked), chance 0..1.

New knob = one field on `VideoSettings`/`AudioSettings`/`AdjustSettings` + its filter; new device/preset = a JSON file.

## Pipeline executions and the audio-only retry (2026-11-27)
- **One count.** An execution = one ffmpeg run that makes or changes the copy: a picture encode or an audio-only redo. `OFM_REPURPOSE_MAX_TRIES` (10) caps them together: `ExecutionPlanner.refuse_over_the_cap` before the first encode (`PipelineSpec.executions` = every stage's `max_attempts` x `tries_per_attempt` + every `audio_retries` entry's `tries`), `budget_left` before each execution. Before: the cap summed `max_attempts` only, so spoof.json's 3x3 + 2x2 + 1x2 ran 15 encodes under a cap of 10 (prod and dev 2026-11-26: "after 15 tries").
- **Picture approved, sound not = audio only.** `audio_swap.py` `AudioSwap` (built by `RepurposeExecutor.picture` from the maker and the approved `EncodeStep`): the first redo moves the approved copy aside (`IMG_1234.picture.mov`), every redo copies its video stream (`-c:v copy`), cuts the source audio with the picture's own timeline (`VideoDraws.timeline`), filters it with new draws, encodes with the picture's `EncodeDraws` (same bitrate, creation time, tags) and writes the copy. About 1.3 s against 23-50 s for an encode; the video packets' md5 is the same before and after (`test_run_repurpose_real.py`). A passing redo deletes the kept file; a failed run deletes both. Devices with a recorder (`iphone17`, `iphone16_usa`) get no `AudioSwap`: a pipeline with `audio_retries` runs on a plain-encode device.
- **No retry passes = the first sound is delivered** (owner 2026-11-27; `PipelineSpec.keep_first_sound`, on in `spoof.json`): the kept file is moved back, the job ends done with `RepurposeResult.kept_first_sound` and the picture run's own report (picture unique, sound matching). Not when the first sound was broken (`verify_audio`): that still fails. Without the switch the run raises "Sound still matches the source after N tries".
- **Who does what** (`pipelines/`): `Pipeline` = the fluent setup, fills one `PipelineSetup` (source, output, spec, first seed, run video, timeout) and builds one `PipelineRun` per `run()`; `ExecutionPlanner` = order, strength, budget; `RepurposeExecutor(setup)` = preset setup, encode, and the `AudioSwap` of the last picture; `ExecutionChecker(setup)` = `verify_audio` (source levels measured once) + `check` / `check_sound_again` -> `Verdict`; `ExecutionRecorder` = the `Execution` list, the log line, the Logfire span, the failure text ("Picture still matches...", "Sound still matches...", "Sound came out broken..."); `ExecutionKeeper` (ABC) = where each execution is kept, `features/repurpose/executions.py` `JobExecutions` appends it to `jobs.meta.executions` as it happens, so a failed or killed job still says what every execution measured.
- **/spoof form and card (2026-11-27):** Mirror = Random (default, the preset's 50%) / Mirrored / Not mirrored (`features/repurpose/constants.py` `MirrorChoice`, a form field, stored in job `params`, passed to `run_repurpose(job_dir, source, seed, mirror, job_id)`, which pins `VideoSettings(mirror=1.0 | 0.0)` on every stage through `Pipeline.video`; Recreate restores it). A done card has "See spoof settings" above Download (`ui.menu_button` + `ui.menu_text` rows): mirror (random or chosen), turn, preset, strength, picture try, audio retries, sound (unique, or still matching with the first sound kept). Restart kwargs: `background/registry.py` `_spoofed` builds exactly those five.

## Findings (2026-10-26, ffmpeg 7.1)
- ffmpeg's `vibrato` is nondeterministic in ffmpeg 8.0.1 (Windows, gyan full): the same chain flips between normal and a full-scale blowup (~30% of runs, any params; bisected 2026-10-30 by repeating identical commands). A blown chain measures like peak-normalized garbage and, after a ceiling limiter, can become a near-DC wall -- which plays as silence. Keep `vibrato` out of `loud` lists; every pipeline's audio check (`audio_check.verify_audio`) exists to catch any remaining source of this class.
- ffmpeg's `noise` seed is fixed by default: identical grain in every copy. Every copy here draws `all_seed`.
- Duplyfi's `aphaser` (in/out gain 0.4 x 0.74) costs ~10 dB, its chorus ~5 dB, `acompressor` at -30 dB ~11 dB: `match_level` measures copy vs source (same trimmed window) and adds it back before the limiter. Stereo reel: within 0.4 dB. A mono source comes out ~3 dB lower: `-ac 2` spreads it at -3 dB per channel (legacy uniqify too).
- `perspective` smears edge pixels instead of filling black; the handheld overscan keeps every edge out of frame.
- `unsharp` is positional `lx:ly:la:cx:cy:ca`; `5:5=0.2` is a parse error.
- Crop/scale round trips lose 1-6 px to even-rounding: the chain ends at the exact output size (numbers, not `iw`).
- ffmpeg 7.1 (Debian) has the `chromaprint` muxer: no fpcalc/pyacoustid needed. `pdqhash` 0.2.8 has no Linux wheel: the Dockerfile's build and test stages install `g++` to build it (runtime copies the compiled venv; libstdc++ is in slim).
- Frame sampling: ffmpeg's `fps` filter picks somewhere inside each slot, so a copy and its source sampled at different rates landed 0.1-0.4 s apart; a plain no-knob re-encode then read PDQ 34-104 bits and pHash 67% on fast handheld reels. Now: `select` on timestamps (first frame at/after each step) + `showinfo` times; the plain re-encode reads 100% on every method. Before the fix, a 0.1 s trim alone "beat" PDQ / dHash (0-17%): a sampling artefact, not a real weakness.
- Checker calibration (2026-10-26, scratchpad `calibrate.py` + `wcal.py`; source 10/s, copy 1/s): 16 unrelated reels, 236 ordered pairs, vs VID_6932 and 10 copies. Two template remakes left out as not unrelated: VID_7646 / VID_6738 and VID_7319 / VID_6932 (same spot, framing and sound, another girl; they match on several hashes and on Chromaprint). Per hash the highest threshold with no unrelated pair matching >= 50% in order, minus one step: PDQ 64 (clean to 91), pHash 12 (clean to 14, VID_3217<-1.mp4 at 16), dHash 6 (clean to 8, IMG_2967<-1.mp4 at 10), wHash 6 (clean to 7, VID_6683<-1.mp4 at 8). Copies caught at those: phash 12 finds low/medium/capcut/iphone17 >= 90%, hard 83%, extreme 67%, hard_sp 82%, extreme_sp 40%, hard_sp + iphone17 40%.
- SSCD / TMK false-positive check (lab pod, 8 test clips, 56 ordered pairs): SSCD median cosine at most 0.47 (threshold 0.75), 0 pairs matched; TMK min(level1, level2) at most 0.42 (threshold 0.7). TMK on a 6 s reel: plain re-encode 0.998, trim 0.3 s + crop 5% + saturation 0.963.
- PDQ is brittle to our handheld edits: `low` (tilt/shake/drift, pHash 5 bits) is ~52 bits on raw frames, 58 normalized; Meta's 31 catches only a plain re-encode (`iphone17`, 2 bits). pHash/dHash carry the verdict for light presets.
