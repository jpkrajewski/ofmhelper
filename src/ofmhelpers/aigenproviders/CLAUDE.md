# aigenproviders

AI providers behind one interface; every model is catalog data. The web app never names a provider or model field.
Providers: kie.ai (`kaiai/`), Higgsfield (`higgsfield/`), RunningHub (`runninghub/`), Elyum (`elyum/`), fake (`fake/`, free, for tests/pages).

/clone cost panel (`clone.clone_pricing`, 2026-11-02, per second of SOURCE video at 720P): kie.ai $0.16 (16 credits/billed s, billed = clip + output), Higgsfield $0.433 (measured: the key saved 2026-11-02 paid $29 for 7 runs / 67 s; its old 60% discount is gone), RunningHub $0.14 ($0.07/billed s), Elyum $0.1584 ($0.0792/billed s). 480P/1080P half/double.

## Shared layer
- `base.py` — `Provider`: `upload`, `submit(spec, payload, idempotency_key)`, `status -> TaskState`, `download`, `default_key()` (the admin's .env key; users only their own); class vars `name`/`label`/`rank`/`needs_key`. `@register_provider` into an `lru_cache`d registry; lookups `provider_class`, `get_provider`, `provider_names`.
- `spec.py` — `ModelSpec` (one catalog entry, `key = "<provider>:<model id>"`). Derives `media_fields`, `form_fields`, `parse_form`, `check` (jsonschema 2020-12, before any upload/payment), `request`. `max_upload_bytes`: a model's own documented per-file limit above its provider's default cap (kie.ai `nano-banana-pro`: 30 MB, docs.kie.ai market/google/pro-image-to-image); `base.uploader(provider, spec)` hands it to `Provider.upload(path, max_bytes)`, so a reference under it goes up as the original file instead of a JPEG copy (user rule 2026-11-01: best-quality input). Every provider's upload cache key carries the limit, so a copy cached under the default cap is never reused. Measured on kie.ai 2026-11-01 (real runs, files sent raw): Nano Banana Pro took a 29.2 MB and a 32.1 MB PNG and a 10000x10000 px PNG (limit set to the documented 30 MB; the 8000 px side cap still applies to it); Wan 3.0 took a 19.5 MB image and an 8000 px side, refused 21.1 MB (422 "file size exceeds limit": limit 20 MB), refused a 127.5 MB video (422) and a 4320 px wide video (422 "resolution is out of range"), and failed a 104.3 MB one after submit ("Internal Error"): videos stay originals, so one over 100 MB or 4096 px fails on kie.ai. Higgsfield Wan 3.0 reference-to-video took 19.5 MB, 21.1 MB and 8000 px images (limit set to the proven 21 MB; its true ceiling is untested above that).
- `catalog.py` — `catalog()`, `get_spec(key)`, `models_for(provider, kind)`.
- `runner.py` — `generate(...)`: resume or submit, poll with backoff, download to `settings.aigen.out_dir`. Timeout leaves the request remembered for recovery. Submit is resent ONLY on `ProviderRateLimitError` (nothing was created): waits `OFM_AIGEN_RATE_LIMIT_WAITS_S` (10/30/60 s, +0-25% jitter) or the error's `retry_after_s`, at most `OFM_AIGEN_RATE_LIMIT_MAX_WAIT_S` (180) in all, then raised; any other submit failure (timeout, 5xx: maybe paid) is raised at once. A result download failing with `ProviderUnavailableError` is tried again after each `OFM_AIGEN_DOWNLOAD_RETRY_WAITS_S` (5/15 s; review #11: one CDN blip cost a paid file); other errors (disk full) raised at once; the request stays remembered either way. Every retry wait goes through `runner._sleep` (tests patch it; the poll keeps `time.sleep`).
- `TaskState.no_credits` — a request accepted, then failed for want of credits: the runner raises `ProviderNoCreditsError` (card "No credits", a /clone-links batch halts), not `ProviderGenerationError`. Higgsfield sets it from a `failed` status whose error says "credit balance" (prod 2026-10-31: "Your credit balance is too low to complete this request. Please top up your balance and try again." -- three /clone runs showed "Failed").
- `tasks.py` — `ProviderTask` per job in Redis (`aigen:task:<job id>`), incl. the key it was made with. Redis errors logged, never raised.
- `errors.py` — `InvalidInputError` + `ProviderError` family (auth/input/generation/unavailable/timeout) + `ProviderNoCreditsError(ProviderInputError)` (empty balance: a batch stops asking) + `ProviderRateLimitError(ProviderUnavailableError)` (`.retry_after_s`; only for "nothing created", never a 5xx/timeout). Adapters map codes onto these -- including answers they cannot parse (non-JSON 200, wrong shape): `ProviderUnavailableError`, so a paid request is polled again and stays resumable instead of a ValueError that makes `run_job` forget it (review #56). A rejected key is always `ProviderAuthError(label, detail)` = "<label>: wrong API key" (provider text in `.detail` + exception note, for logs).
- `base.upload_lock(cache_key)` — one upload per file across worker processes (Redis lock `lock:<cache_key>`, `OFM_UPLOAD_LOCK_S`); Redis down (lock creation or acquire) = no lock, upload anyway; a lock lost mid-upload = release warning only. `cache_key` is logged, so it never carries an API key (providers hash it).

## Adding a provider
1. `<name>/provider.py` (`@register_provider`), `models.py` (wire format, `extra="ignore"`), `client.py` only without an official SDK.
2. `<name>/catalog.json`: `{model_id, label, family, kind, input_schema[, fixed, default_prompt]}`; generate it if the provider publishes schemas.
3. Map failures to `errors.py`, statuses to `TaskState`. Wire-level faked tests.
4. `<name>/fake.py`: the provider's wire faked for OFM_FAKE_EXTERNALS (requests via `utils/outbound.py` routes, httpx via a `MockTransport`), one `FAKE_KEY` accepted; add it to `tests/contract/test_ai_provider_contract.py`.
Nothing else changes. For /clone: one `CloneTarget` in `clone.py`.

## Fakes (OFM_FAKE_EXTERNALS)

- `higgsfield/fake.py` — `install(client)` puts an httpx `MockTransport` under the SDK (its `_client`/`_upload_client` cached properties, higgsfield-client 0.2.0); `FAKE_KEY` only (else 401); queued 2 polls, then completed; result/upload host served to `requests` too.
- `base.Provider.download` goes through `utils/outbound.get`.
- Wire behaviour (success after 3 polls, 4xx, 5xx, timeout, maintenance, rate limit resent then paid once / persisting, unreadable answers stay remembered, result download retried, failed, rerun resumes, never resubmits otherwise): `tests/integration/aigenproviders/test_provider_wire_behaviour.py`, bodies in `tests/fixtures/providers/`; runner logic against an in-memory provider: `test_runner.py`.

## kie.ai (`kaiai/`, typo kept for imports)
- `client.py` — the transport retries GET/HEAD only (a createTask is never resent by it — paid twice); the runner resends a createTask only on code 429 (docs.kie.ai: "Rejected requests will not enter the queue"). Errors via `models.raise_for` (401/403 auth, 402 `ProviderNoCreditsError`, 429 `ProviderRateLimitError` (HTTP Retry-After read when present; in-body has none), 408/455/5xx `ProviderUnavailableError` (455 maintenance is not resent), else input). An answer that is not JSON or not the model's shape (`_parsed`), or a SUCCESS whose `resultJson` cannot be read (`KieProvider._result_urls`), is `ProviderUnavailableError` "unreadable". Audit logs `tasks.jsonl`, `completions.jsonl`. Upload memo in Redis keyed `kieai:upload:<sha256(key)[:16]>:<path>` (`_upload_cache_key`; the raw key was in Redis key names and lock warnings until review #27), HEAD-checked; oversized images uploaded as a shrunk JPEG copy.
- Key `KIE_AI_API_KEY_ADMIN` (admins' default). No idempotency key; re-runs resume.
- `catalog.json` — 152 models (66 image, 86 video), generated by `scripts/sync_kie_catalog.py` (run in the tests container; network only there). The 17 hand-made entries (`CURATED` in the script: schemas tuned to what the old wrappers sent, `fixed`, `default_prompt`) are kept verbatim; every other entry keeps its `label`/`family`/`fixed`/`default_prompt` and gets a fresh `input_schema` per run; entries gone from the docs are kept (jobs name them). Re-running is idempotent.
- Findings (2026-10-22, docs.kie.ai):
  - `https://docs.kie.ai/llms.txt` lists every page; each `<page>.md` embeds the OpenAPI 3.0 YAML of its request. Every generation model -- Market, Veo 3.1, Runway (+Aleph), 4o Image, Flux Kontext, Suno -- is now `POST /api/v1/jobs/createTask` `{model, input}` + `recordInfo`; no separate endpoints any more except Gemini Omni audio/character (`/api/v1/omni/{audio,character}/create`).
  - Docs quirks the script normalises: `oneOf` input variants (Kling 3.0 Omni, PixVerse extend) -> one form (union of fields, required = in every variant) + `anyOf` of the variants for `check`; bogus `allOf: [{type: string}]` on objects (Kling 3.0 Omni) dropped; `pattern` dropped (`^.*\S.*$` rejects multi-line prompts, `^(https?|oss)://` rejects the local paths `check` uses); deprecated fields dropped; an input named `model` (Veo `veo3_fast`, Veo extend `fast`, Flux Kontext `flux-kontext-pro`) collides with /ai/run's own field, so it is pinned in `fixed` to the docs default; `nsfw_checker` pinned false like the curated entries.
  - Not added: 31 Music pages (ElevenLabs, Gemini TTS, Suno -- audio output; runner/`ModelChoice` handle image/video only), 42 Chat pages, Gemini Omni audio/character (own endpoints), Grok Image 2.0 segment-map + OmniHuman human-identification/subject-detection (answer `resultObject` only; `KieRecord.result_urls` reads `resultUrls`), PixVerse reference-to-video (requires `image_references`, an array of objects the form cannot fill), Veo "Get 1080P" (no model id in its spec).
  - Follow-up models take a previous kie task id as a text field (Grok extend/upscale, Runway/Veo extend, Veo get-4k, Seedance 2.5 draft, Grok segment-edit).
  - Prices: `POST https://api.kie.ai/client/v1/model-pricing/page` `{pageNum, pageSize<=100, modelDescription:"", interfaceType:""}` (what kie.ai/pricing calls; 590 rows). Dearest per run: Seedance 2 4K $1.04/s, Seedance 2.5 1080p $0.79/s, Kling 3.0 / 3.0 Omni 4K $0.335/s, Vidu Q4 4K $0.31/s, Wan 3.0 Prime 1080p $0.25/s, HappyHorse 1.0 1080p $0.24/s; per clip Veo 3.1 Quality 4K $1.85, Kling 2.1 Master 10 s $1.60, Wan 2.6 15 s 1080p $1.58, Gemini Omni 4K $1.26; Kling AI Avatar Pro $0.08/s of audio (up to 5 min).

## Higgsfield (`higgsfield/`)
- Official SDK `higgsfield-client` 0.2.0. Key `KEY_ID:KEY_SECRET` (`HF_API_KEY_ADMIN`, admins' default). Uploads only JPEG/PNG/WebP/GIF/WAV/MP4. A .mov/.m4v/.webm/.mkv reference goes up as an MP4 copy (`utils/video_mp4.py`, in `out_dir/higgsfield/mp4`, `OFM_HF_VIDEO_CONVERT_TIMEOUT_S` 900); one ffmpeg cannot read = `ProviderInputError` "Could not turn <name> into an MP4 video" before any call (prod 2026-11-02: an iPhone .mov failed /clone with "Higgsfield takes ... not ...__Video-21956.mov"). BMP/TIFF as a JPEG copy (`fitted`).
- `catalog.json` generated (83 models) by `scripts/sync_higgsfield_catalog.py`.
- Findings (2026-10-18, docs.higgsfield.ai): base `https://api.higgsfield.ai`, header `Authorization: Key <id>:<secret>`; statuses queued/in_progress/completed/failed/nsfw/canceled; uploads via presigned URL (1 h, PUT without key); outputs kept ≥7 days. The SDK retries submits without an Idempotency-Key — rare double charge possible; a job never resubmits once it has a request id.

## RunningHub (`runninghub/`, 2026-10-31)
- Standard Model API (`https://www.runninghub.ai/openapi/v2/*`, docs `https://www.runninghub.ai/runninghub-api-doc-en/llms.txt`, each page `<page>.md` with its OpenAPI): every model is `POST /openapi/v2/<model path>` with a plain JSON body, `Authorization: Bearer <key>`; `POST /openapi/v2/query {"taskId"}` -> `status` CREATE/QUEUED/RUNNING (pending), SUCCESS (`results[].url`), FAILED/CANCEL, `usage.consumeMoney`; upload `POST /openapi/v2/media/upload/binary` (multipart `file`) -> `data.download_url`, signed for 24 h (cached per account + path for `OFM_RH_UPLOAD_CACHE_TTL_S`, 20 h, one upload per file across workers). The ComfyUI workflow / AI app API (`/task/openapi/*`) is not used.
- HTTP 200 with the code in the body (`errorCode` string on tasks, `code` on uploads); `models.raise_for` maps the docs' table: auth 412/435/436/801/802/806/811/1002/1014/1602 (1014: the model API takes **Enterprise-Shared keys only**), no balance 416/812 (`ProviderNoCreditsError`, also on a FAILED task: `TaskState.no_credits`), rate/concurrency 415/421/814/1003/1011/1520 (`ProviderRateLimitError`, nothing created), content 1501/1505 ("Photorealistic real people are prohibited": `ProviderGenerationError`, card "Flagged content"), transient 500/808/1000/1005/1006/1010/1012/1015/1504/1517/1519, else input. A wrong key's upload answers code 1 "ApiKey verification failed".
- **No idempotency key**: a submit is sent once, never retried by the client (the runner resends only on a rate-limit refusal); our job id only goes into the submit log line.
- `catalog.json` — 324 models (225 video, 99 image), generated by `scripts/sync_runninghub_catalog.py` (reuses the kie.ai script's OpenAPI cleaning): model id = the path after `/openapi/v2/`; the docs' example values are not defaults (dropped on prompts and media fields: sample asset URLs); camelCase `...Url(s)` fields get `x-media`; a string enum of whole seconds (`duration` "auto","2".."30") becomes an integer range marked `x-wire: string`. `provider.wire_body` sends every schema default the payload left out (RunningHub requires `aspectRatio` etc.) and `x-wire: string` fields as strings. Audio/3D/Other pages and 4 models with fields the form cannot fill are skipped.
- /clone: `CLONE_TARGETS["runninghub"]` = `alibaba/wan-3.0/reference-to-video` (`imageUrls`, `videoUrls`, `audio`, `aspectRatio`; billed output + min(reference, 15) s). The cost panel uses $0.07 per billed second at 720P (user's account, 2026-11-02) in dollars per source second (`OFM_CLONE_RH_USD_PER_VIDEO_S`; `POST /openapi/v2/price-preview/<model path>` with a key answers an exact one). Motion-transfer models also there: `rhart-video/wan2.2/character-motion-transfer`, `kling-v3.0-pro/motion-control`.
- Key `RUNNINGHUB_API_KEY_ADMIN` (admins' default), `OFM_RH_BASE_URL` (runninghub.cn is a separate site and account). Fake `runninghub/fake.py` (`FAKE_KEY`, `refuse_next`, `fail_next`); tests `tests/integration/aigenproviders/runninghub/`, contract `tests/contract/test_ai_provider_contract.py`.
- Unverified until a real key runs: whether a failed task is billed, how long result URLs live (downloaded at once), real-person handling on Wan 3.0 (1505).

## Elyum (`elyum/`, 2026-11-02)
- Public API `https://api.elyum.ai/v1` (docs elyum.ai/open/docs, /open/docs/mcp; `llms.txt`), `Authorization: Bearer ek_live_...`, key scopes `generate` + `spend`. One endpoint for every model: `POST /v1/generations {model, prompt, inputs[], duration, resolution, aspect_ratio, audio}` -> `g_...`, `GET /v1/generations/{id}` -> `status` queued/running (pending), succeeded (`outputs[].url`, signed 24 h), failed/canceled (`error {code, message}`: content_refused/timeout/generation_failed), `usage.usd`. Upload `POST /v1/files` (multipart `file`, PNG/JPG/WebP/MP4/MOV/WebM/MP3/WAV, 60 MB) -> `file_...` id, cached per account + path `OFM_ELYUM_UPLOAD_CACHE_TTL_S` (20 h; lifetime undocumented). Billed on delivery, failed/canceled free.
- `provider.wire_body`: the catalog's media fields (`image_urls`, `video_urls`, role from our `x-role`, default `reference`) become `inputs` `{role, file|url}` in field order; the rest goes as is; `@Image1`/`@Video1` in the prompt become Elyum's `@image1`/`@video1`. /clone: `CLONE_TARGETS["elyum"]` with `aspect=None` (no "adaptive" on Elyum: left out, the model follows the inputs).
- **Idempotency-Key** = our job key on every create: a resend returns the same generation (`Idempotent-Replayed`). Errors (`models.raise_for`, real HTTP status + envelope `error.code`): auth/scope = `ProviderAuthError`; insufficient_balance (402), key_cap/member_budget/client_budget (429) = `ProviderNoCreditsError` ("insufficient balance", card "No credits"); concurrency/rate_limited (429), model_unavailable/option_unavailable/maintenance (503, nothing charged) = `ProviderRateLimitError` (`retry_after`); other 5xx unavailable; else input. Unreadable 2xx = unavailable.
- Upload copies: .mkv/.m4v -> MP4 (`utils/video_mp4`, `OFM_ELYUM_VIDEO_CONVERT_TIMEOUT_S`), BMP/TIFF or over-limit images -> JPEG (`fitted`); anything else not taken, or over `OFM_ELYUM_MAX_FILE_BYTES`, = `ProviderInputError` before any call.
- `catalog.json` hand-made (no schema endpoint without a key): `alibaba/wan-3.0/reference-to-video` (up to 10 images + 5 clips; resolution 480p/720p/1080p default 1080p, duration 2-30 default 5, audio default true, aspect 16:9/9:16/1:1/4:3/3:4) and `alibaba/wan-3.0/text-to-video` (the contract test's cheapest: 480p 2 s ≈ $0.08). Wan 3.0 price $0.0396/$0.0792/$0.1584 per s of clip + output; "usually takes about 12 min".
- Key `ELYUM_API_KEY_ADMIN` (admins' default), `OFM_ELYUM_BASE_URL`. Fake `elyum/fake.py` (`FAKE_KEY`, `refuse_next` (status, code, message), `fail_next` (code, message), `created`, `uploads`); tests `tests/integration/aigenproviders/elyum/`, contract `tests/contract/test_ai_provider_contract.py`.
- Unverified until a real key runs: the reference-to-video model id (docs only spell out `.../text-to-video`; `GET /v1/models/alibaba/wan-3.0` with a key lists the tasks), whether prompt cites are case-sensitive, how long `file_...` ids live.

Callers: `web/routers/generation/ai.py`, `clone.py`, `web/recovery.py`, `web/api_keys.py`, `web/schemas/generation.py`.
