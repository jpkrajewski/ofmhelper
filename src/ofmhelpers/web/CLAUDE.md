# web

FastAPI app ("Ascend Global LLC — Content Ops"): users who sign in with Google, Apple or email + password (`ofmhelpers.signin`), each owning their own phones/accounts/reels/jobs/files/API keys (admins too: nobody sees another person's), AI generation, media download/cleaning, landing-page CRM, file manager. Jinja2 pages + a small vanilla-JS polling layer.

## Users and ownership (2026-10-22)
- `users` (+ `user_identities`, `password_links`, `user_api_keys`; alembic c2d3e4f5a6b7). Roles: admin (/users + admin tools) and user. The VA role is gone: its jobs and the admin's belong to the password admin (email "admin").
- Owned (`user_id`, ON DELETE RESTRICT, alembic d3e4f5a6b7c8): devices, logins, tracked_accounts, creators, watched_profiles (PK user_id+username; a username is scanned once, written to every owner's row), profile_groups. Uniques are per owner (two users may both have "Phone 01" or track one handle; a login never links across owners, so nobody reveals another's password). Drive folders follow the login; the sweep shares each with its owner's Google account (`shared_with`). A user who owns rows cannot be deleted: deactivate.
- **Everyone sees and acts on only their own data, admins included** (2026-10-22). An admin's extra power is managing people (/users) and the admin-only tools (file manager, action log, applications, character sheet), never reading another user's phones/accounts/reels/jobs/Drive/files.
- Requests: `AuthMiddleware.scope(request)` (always the user's own id) for reads/writes on existing rows, `owner_id(request)` for new rows, `actor(request)` for jobs (actor = user id string). Store `owner=None` ("everyone's") is for system work only -- the sweeps (drive_loop, reel_watch, account_tracker, recovery); no request passes it. Stores take `owner`/`user_id`; a store call without one acts as the agency (`stores.users.agency_id()` = password admin).
- Assets: everyone `assets/users/<id>/`; the agency (password account) keeps the store root, where its files predate per-user folders, minus `users/` (`in_asset_root`: listing, serving and reuse checks).
- API keys: /account saves a user's own per provider (encrypted); forms pre-fill them; an admin with none falls back to the .env key; a user never gets the .env key.
- Cookies (2026-10-22): `/cookies` (`routers/cookies.py`, every user, More menu) uploads/replaces/removes the user's OWN cookies.txt: `user_cookies` (alembic b1c2d3e4f5a7, `EncryptedText`, PK user_id), `stores/cookies.py` (repository caches nothing). The page shows file name, upload time, domains, cookie count, Instagram login + expiry -- never a value. Whose cookies work uses: a download job = whoever started it (`user_id` kwarg, cookies read in the worker, never in RQ/Redis); a tracked account's scan = its owner; a watched profile's single shared scan = the earliest-added watcher who has cookies, else none (`for_watched`, the only cross-user use; the value never leaves the worker). Upload queues `unlock_gated(user_id)` (their watched profiles' login-only reels) and `rescan_limited(user_id)` (their limited accounts). The old shared `OFM_COOKIES_FILE` became the password admin's by the revision (file left in place; `migrate` mounts `cookies_data` read-only).

**New background-job tool?** Reuse `stores/jobs.py` + `routers/task_helpers/` + one router file; no new plumbing.

## Layout
`main.py` (assembly only), `api_keys.py`, `phones_workbook.py`, `middleware/`, `recovery.py`, `reel_watch.py`, `account_tracker.py`, `drive_folders.py`, `ref_usage.py`, `schemas/`, `templates_config.py`, `stores/`, `db/`, `routers/`, `templates/`, `static/`.
Dependency direction: **routers -> stores -> db**. Routers never open sessions; stores never render or raise `HTTPException`.

## Top-level files
- `main.py` — calls `configure_logging()`; middleware, static, lifespan (job history, recovery + reel + account + drive sweepers), loop over `routers.ROUTERS`. Last `add_middleware` runs first: Session -> WriteRateLimit -> Auth.
- `middleware/auth.py` — all auth on `AuthMiddleware`: session gate (user re-read every request via cached `stores.users.get_user`; gone/deactivated or password changed since sign-in (`credential_stamp` in the session; the changing session is re-remembered) -> session cleared, role change applied), `sign_in` (fresh session), `user`, `is_admin`, `require_admin`, `scope`, `owner_id`, `actor`. Allowlist `settings.web.public_paths`/`public_prefixes` (incl. `/auth/`, `/password/`). Unauthenticated: page -> 303 `/login?next=`, fetch -> `401 {"login_url"}`.
- `middleware/compression.py` — outermost; gzip level 6 for >= 1 KB, never media or `application/octet-stream` (host nginx gzips text/html only).
- `middleware/ratelimit.py` — counts failed logins only; `WriteRateLimitMiddleware` per-IP cap on writes. Redis errors fail open. Client = `request.client.host`: uvicorn `--proxy-headers --forwarded-allow-ips 127.0.0.1,172.16.0.0/12` (Dockerfile), never `*` (nginx appends to X-Forwarded-For; `*` takes the client-written leftmost entry, 2026-10-22).
- `api_keys.py` — form pre-fills: the user's saved keys; admin falls back to `Provider.default_key()` (.env).
- `drive_uploads.py` — /clone "Upload to Drive": queues a run's videos into an account folder the clicker may use (`drive_uploads` table, alembic e4f5a6b7c8d9; one per file+folder, failed ones retry, so do ones `queued` longer than `OFM_GDRIVE_UPLOAD_STALE_S` (1 h: worker killed mid-batch); enqueue failure or any per-file exception marks the row failed with the reason; before writing, the worker checks the folder's `root_folder_id` is the owner's `drive_folders.usable_root` (stored root, name-checked outside production) -- a dev DB copy holding the live root is refused, even before any sweep; the answer lists only runs the clicker may see), uploads on the worker as the clicker's Google account (`gdrive.connect_as`, refresh token from `stores.users`; the bot cannot upload). Named like Download (`download_names.py`).
- `reel_thumbs.py` — `/reels/thumb/{code}`: IG cover fetched once (`outbound.get`), 270px webp under `<uploads>/.previews/reels/` (covers were 64-284 KB each and their URLs expire).
- `download_names.py` — camera-roll result names (moved out of routers: `drive_uploads` needs it).
- `ref_usage.py` — last-picked reference files, one Redis sorted set per user (`refs:used:{id}`); errors swallowed.
- `reel_watch.py` — sweeper: claims profiles older than `rescan_interval_s` (12 h), one sequential worker job, claims expire (`rescan_claim_ttl_s`). Per profile up to 1 + `proxy_retries` proxies; transport-failing proxies leave the pool. **A profile with a good scan is never removed** ("not found" also hits flagged proxy IPs — 36 real profiles lost 2026-10-17). A just-added profile is dropped only if private, or not found everywhere *and* the logged-in check agrees.
- `account_tracker.py` — `/accounts` sweeper (`ofmhelpers.socials`, any platform): claims accounts older than `OFM_ACCOUNTS_RESCAN_INTERVAL_S` (6 h), queues per-platform jobs of `batch_size` with staggered `ProxyPool` start; per account up to 1 + `proxy_retries` proxies. Rate-limited on every try / direct connection down -> batch stops, claims expire (`claim_ttl_s`). Never-reached tries record nothing; answered failures record `error`, previous numbers stay. Accounts are never auto-removed.
- `drive_folders.py` — /drive, all through the phone owner's OWN Google account (`gdrive.connect_as` + their sign-in refresh token): no service account, no configured folder id (2026-10-22). Each owner has one root in their own Drive, `root_name()` = "ALL ACCOUNTS" in production / "DEV - ALL ACCOUNTS" anywhere else (dev never sees the live folders, even with the same Google account), a stored root not named `root_name()` is never used outside production (a dev copy of the prod DB holds the live id: found by name instead, the live folder untouched; `/drive/live` forgets it), found by name in any case (prod's hand-made "all accounts" is adopted with its 10 folders) or made, kept as `users.drive_root_id`. Inside: "<handle> - <owner>" per Instagram login on an active phone + `POSTED` (people move posted videos in). `sync()` (loop every `check_interval_s` + Sync), advisory lock, per owner: owners without Google listed in `SyncReport.not_connected`, nothing made for them; (1) make what the DB says is missing (find by name before create, POSTED any case, kept by id, renamed back); (2) `_tally` per account in parallel (own connection per thread): heals gone/trashed/renamed/dragged-out folders, records files first seen in POSTED ("posted today/7 days", `OFM_GDRIVE_TIMEZONE`), saves the read (`scan`). `store.account_folders()` = rows in each login owner's CURRENT root only (old roots, prod rows in a dev DB copy: ignored, remade). `board(owner, viewer, live)`: `/drive` renders the saved reads (no Drive call), `/drive/live` reads per owner: root once, folders in one `children_of` batch, POSTED in another (3 calls per owner), missing ones the slow way (only the root's own check forgets the root; a batch 404 -- one account/POSTED folder deleted meanwhile -- falls back to one by one); the viewer's own root's unowned folders listed. Previews `/drive/thumb/{login}/{file}` through the folder owner's account, only files in that login's folders, image kept on disk. Never deletes or moves anything. Admin takeover: the first `OFM_ADMIN_EMAILS` address's first Google sign-in becomes the password account (`users.is_password_account`, same id: all agency data theirs).
- `previews.py` — gallery stand-ins for results (slow connections; prod 2026-10-21: 4K clone exports ~28 Mbit/s never showed). Video: 720p, `preview_maxrate` 1500k, faststart mp4 + first-frame webp poster (`poster_size`); image: webp <= `image_preview_px` (1024, hover zoom). Cached in `<uploads>/.previews/{job}_{i}...` (`previews_dir()`, read per call). `warm_previews(job_id, Job.local_paths())` makes them: queued by `stores/jobs.run_job` on finish on the `previews` RQ queue, consumed by compose `preview-worker` (1 process, `nice`, 2 CPUs, ffmpeg `-threads 2`). Measured on prod files: 32–51 MB export -> 0.5–1.5 MB in ~7 s; 7 MB PNG -> ~60 KB.
- `preview_backfill.py` — one pass at startup (Redis guard `previews:backfill`, `preview_backfill_guard_s`): queues every done job missing previews, newest first. Lists via `list_finished_jobs` — **never `list_jobs`**, whose self-heal deletes jobs with missing files (wiped 277 dev jobs on a prod snapshot, 2026-10-21).
- `media_kinds.py` — `classify_kind` + extension sets, import-free (previews and stores need it without importing routers).
- `recovery.py` — every 300 s, settles remembered provider requests: running -> wait; done/deleted/too old -> forget; failed poll -> one `status` call; done -> re-run via `registry.RESUMABLE` (resumes, never pays twice).
- `schemas/` — `persistence.py` (`Job`), `generation.py` (`ProviderChoice`, `ModelChoice`), `gallery.py` (`JobCard`, `TaskCard`, `CloneCard`/`CloneBatch`).
- `phones_workbook.py` — /phones Excel export (openpyxl write-only): sheet Phones (row per phone, per service any phone uses: usernames/passwords, social backup codes; several logins one cell, newline-joined; custom = "Provider: user") + sheet Logins (row per login per phone). Every cell forced to string type (a password starting `=` must not become a formula). Plaintext on purpose (VA tool).
- `templates_config.py` — `get_templates()`; `static_url()` adds `?v=<hash>` to every CSS/JS link (nginx caches `/static` a week). `render_polled`: ETag + `no-cache`, 304 while unchanged — for fragments live-gallery.js polls (`/generate/gallery/latest`, `/clone/batches`); the browser revalidates itself. Needs byte-stable renders (hence `download_name` digits hash the file name).

## stores/
- `jobs.py` — `create_job` -> `enqueue(run_job, ...)` -> `get_job`. `run_job` stores only the error message. Results live in the job's JSONB `result`. Pages use `list_jobs_page(tasks, offset, limit, actor)`: SQL filter/slice, heals only the page.
- `applications.py` — landing-page leads; write-once.
- `tracked_accounts.py` — /accounts: `list_accounts` (growth baselines per `growth_windows_h`), `get_account`, `get_history`, creators, notes, `record_scan` (one transaction: account row lock, upsert `tracked_posts` within retention, widen `covered_since`, snapshot, age-prune; see socials/CLAUDE.md). View windows are never stored — `TrackedAccount.window(days)` derives any period on read from the kept posts' views/dates (the list loads only those two columns).
- `drive_folders.py` — /drive: `targets()` (Instagram logins on active phones, from `devices.list_devices`), stored account + POSTED folder ids (`DriveFolderRepository`; a new account folder id drops the POSTED id; rows cascade with the login, Drive keeps the folder), `record_posted` (insert-only, `ON CONFLICT DO NOTHING`: a file counts once), `posted_counts(since)`. `drive_day_folders` is a retired table (alembic `RETIRED_TABLES`): kept for a rollback, never read.
- `devices.py` — /phones: `list_devices` (no secrets; logins linked to /accounts row via `LoginService.tracked_platform` + handle), `secrets(login)`, `export_devices` (decrypted), add/update/retire/restore/delete phone, add (link-or-create)/update/remove login. Raises `DuplicateError` and `VaultError`.

## db/
`models.py`, `session.py`, `encrypted.py` (`EncryptedText` Fernet column; `VaultError` on missing/wrong key, never blank), `repositories/` (only DB code; inherit `cached_repository.py`). `DeviceRepository` caches **no** read: they return decrypted secrets, which must never reach Redis. ## Phones <-> /accounts
- Adding or renaming a phone login of a service with `tracked_platform` (services.json; Instagram today) tracks it on /accounts and queues its scan (`account_tracker.track_login`, called by the phones routes). Revision f4a5b6c7d8e9 did it once for logins saved before. Removed-by-hand accounts come back only when such a login is added again.
- Logins link to their account by `(tracked_platform, platform.handle(username))` (`stores/devices._linked`), carrying `tracked_account_id` + `tracked_followers`; /phones shows "12.3k followers" per login and sorts by `Device.followers` (the most-followed account on it) by default (`PhoneSort.FOLLOWERS`; untracked phones last).
