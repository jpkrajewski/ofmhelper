# web

FastAPI app ("Ascend Global LLC — Content Ops"): users who sign in with Google, Apple or email + password (`ofmhelpers.integrations.signin`), each owning their own phones/accounts/reels/jobs/files/API keys (admins too: nobody sees another person's), AI generation, media download/cleaning, landing-page CRM, file manager. Jinja2 pages + a small vanilla-JS polling layer.

## Users and ownership (2026-10-22)
- `users` (+ `user_identities`, `password_links`, `user_api_keys`; alembic c2d3e4f5a6b7). Roles: admin (/users + admin tools) and user. The VA role is gone: its jobs and the admin's belong to the password admin (email "admin").
- Owned (`user_id`, ON DELETE RESTRICT, alembic d3e4f5a6b7c8): devices, logins, tracked_accounts, creators, watched_profiles (PK user_id+username; a username is scanned once, written to every owner's row), watched_profile_groups. Uniques are per owner (two users may both have "Phone 01" or track one handle; a login never links across owners, so nobody reveals another's password). Drive folders follow the login; the sweep shares each with its owner's Google account (`shared_with`). A user who owns rows cannot be deleted: deactivate.
- **Everyone sees and acts on only their own data, admins included** (2026-10-22). An admin's extra power is managing people (/users) and the admin-only tools (file manager, action log, applications, character sheet), never reading another user's phones/accounts/reels/jobs/Drive/files.
- Requests: `AuthMiddleware.scope(request)` (always the user's own id) for reads/writes on existing rows, `owner_id(request)` for new rows, `actor(request)` for jobs (actor = user id string). Store `owner=None` ("everyone's") is for system work only -- the sweeps (`sweeps.py`: drive, reel_watch, account_tracker, recovery); no request passes it. Stores take `owner`/`user_id`; a store call without one acts as the agency (`stores.users.agency_id()` = password admin).
- Assets: everyone `assets/users/<id>/`; the agency (password account) keeps the store root, where its files predate per-user folders, minus `users/` (`in_asset_root`: listing, serving and reuse checks).
- API keys: /account saves a user's own per provider (encrypted); forms pre-fill them; an admin with none falls back to the .env key; a user never gets the .env key.
- Cookies (2026-10-22): `/cookies` (`routers/cookies.py`, every user, More menu) uploads/replaces/removes the user's OWN cookies.txt: `user_cookies` (alembic b1c2d3e4f5a7, `EncryptedText`, PK user_id), `stores/cookies.py` (repository caches nothing). The page shows file name, upload time, domains, cookie count, Instagram login + expiry -- never a value. Whose cookies work uses: a download job = whoever started it (`user_id` kwarg, cookies read in the worker, never in RQ/Redis); a tracked account's scan = its owner; a watched profile's single shared scan = the earliest-added watcher who has cookies, else none (`for_watched`, the only cross-user use; the value never leaves the worker). Upload queues `unlock_gated(user_id)` (their watched profiles' login-only reels) and `rescan_limited(user_id)` (their limited accounts). The old shared `OFM_COOKIES_FILE` became the password admin's by the revision (file left in place; `migrate` mounts `cookies_data` read-only).

**New background-job tool?** Reuse `stores/jobs.py` + `routers/task_helpers/` + one router file; no new plumbing.

## Layout
`main.py` (assembly only), `api_keys.py`, `phones_workbook.py`, `middleware/`, `recovery.py`, `reel_watch.py`, `account_tracker.py`, `drive_folders.py`, `ref_usage.py`, `schemas/`, `templates_config.py`, `stores/`, `db/`, `routers/`, `templates/`, `static/`.
Dependency direction: **routers -> stores -> db**. Routers never open sessions; stores never render or raise `HTTPException`.

## routers/
`routers/__init__.py` `ROUTERS` = the registration list: new page = one import + one entry.

**How a route is written (2026-11-03):**
- Who is asking: typed parameters from `web/dependencies.py` (`user: CurrentUser`, `actor: Actor`, `owner_id: OwnerId`, `scope: Scope`, `assets_root: AssetsRoot`, `api_keys: ApiKeys`), router-level `dependencies=[AdminOnly]`. Never `AuthMiddleware.scope(request)` in a route. Helpers take plain values, not the request.
- A form of 3+ fields, or shared by routes: `form: Annotated[XForm, Form()]`, `class XForm(FormModel)` in the router (`web/forms.py`; `PaidForm` adds `api_key` + `provider`). 1-2 fields stay `Annotated[str, Form()]`.
- Measured on FastAPI 0.143.3, against its docs: a form model next to a separate `File()` param is 422 `body.form: Field required` whatever is sent, so files go inside the model (`image: Files`); a form model keeps a blank field as "", so `FormModel` drops exact "" (spaces stay a value: a paid `batch` of spaces must stay a 422, not lose the pay-twice guard).
- A refusal worded for the page stays an `HTTPException` in the route or a feature error. Not a validator: that answers 422, and `generation.js` shows a non-string `detail` as "[object Object]".
- A feature's refusal: one row in `web/exceptions.py` `REFUSALS`, no try/except per route. Only errors worded for the person. `VaultError` is not one: `phones.py` puts `_vault_reason` on the routes that use a secret, because on the whole router the list page answered raw JSON and lost its crash log.
- 422s never carry `input` (`exceptions.invalid_request`): FastAPI's default echoes the whole form on a missing field, API key included.
- Gallery: `gallery = Gallery({TASK})` (`web/gallery.py`), `query: GalleryParams` + `gallery.page(actor, query)` on `/gallery`, `gallery.page(actor)` elsewhere. A plain object, not a class dependency (the FastAPI skill: avoid those). It shows shown jobs only: a page listing hidden ones too keeps `list_jobs_page`.
- A path param stays on the route and the lookup is a plain call (`preset = _visible(preset_id, owner_id)`): behind a dependency alias, ruff FAST003 fails and the id leaves the trace's arguments.
- Telemetry shows an argument's value only for an allowed name holding a plain value, and reads a `LoggedFields` model (a form, a gallery's query) field by field (`telemetry._logged_arguments`): a dependency's result never reaches Logfire, whatever it is called.
- `start_job` adds `job_id` to the run's kwargs: not for a worker function that does not take it.
- Every route has a return type (`-> Response` for pages, redirects and files, the model for JSON; `test_request_shapes.py` fails otherwise).
- Against the FastAPI skill, measured on 0.143.3: a route that streams by `yield` answers a refusal raised before its first yield as `200` with an empty body, so `/clone-links/previews` keeps returning a `StreamingResponse` (its no-Drive, bad-paste and unknown-resolution refusals must stay 400s; pinned in `test_request_shapes.py`).

**Shared plumbing:**
- `task_helpers/` — shared upload -> job -> poll -> download: `ASSETS_ROOT` (sha256-deduped store; `assets_root_for(request)`/`assets_root_for_user` — own `users/<id>/`, agency the root minus `users/`; workers get `assets_root` kwarg), `build_ordered_paths` (manifest of new+reused files; the only `record_use` caller), `job_assets`/`serve_job_file` (both result shapes), `add_job_routes` (status page, poll, file, `/files/{job}/{i}/preview|poster` — made on request if not warmed; a failed preview serves the original; immutable cache headers on originals and previews). `asset_card`: `preview_url` for a local image/video, `poster_url` for a video; galleries use them, Download stays on the original.
