# web/routers/inventory

### inventory/
- `phones.py` — `/phones`: card per phone = its back drawn from the catalog (`GET /phones/drawing.svg?model=&color=`, `ofmhelpers.features.phones.catalog.render`, cached a day) + label, model · color, owner, number, then logins as flat rows in `services.json` order (iCloud, Instagram, Gmail first; Iconify logo, service, username; first 2 in both layouts, rest behind "N more"; no logins = "No logins yet"; Open analytics is the first row tool). The page never holds a secret: Show / Copy / Edit / recovery codes fetch one login from `GET /phones/logins/{id}/secret` (`no-store`, logs role + id, never values). Toolbar: instant search (`data-search`, no secrets), filters/sort as query string (`schemas.PhoneQuery`), grid/list (localStorage). Everyone views, reveals and downloads `GET /phones/export.xlsx` -- their own phones only. Everyone also edits their own phones (`tests/integration/web/test_ownership.py`; another person's phone is a 404, admins included): `POST /add`, `/{id}`, `/{id}/retire|restore|delete`, `/{id}/logins` (an account already saved is linked, never copied; a different password is a 409), `/logins/{id}` (edits it on every phone), `/{id}/logins/{login}/delete` (unlinks; deleted when no phone has it). Delete removes a phone and the logins only it had. Duplicate 409, vault problem 500 with reason. `phones.js`.
- `drive.py` — `/drive`: each card says **Waiting: N** (one number, no split by kind) and ends with **Uploaded to Drive today: N** (2026-11-12, owner; it replaced "Posted today"; the clone / manual split is counted, `DriveCard.uploaded_today`, but not shown: the owner found the two extra numbers too much): the files in the account folder or its POSTED whose Drive `createdTime` is today (`OFM_GDRIVE_TIMEZONE`'s calendar day, `features/drive/folders.py` `_count_uploaded`, from the saved read: no Drive call, no table), Clone = the ones /clone's "Upload to Drive" made (`drive_uploads.drive_file_id`, `made_here`), Manual = the rest (put there by hand in Drive). A file moved to POSTED the same day still counts; one deleted the same day does not; /trials (TRIALS folder) and /clone-links (GOOD / TRIAL REELS) uploads are other folders, not counted. No page-level KPI line. Card per Instagram login, the /phones card shape (2026-10-22: drawing, label, `model · color · owner` on one line since 2026-10-24; `@handle` + its Drive folder where /phones lists logins; grid/list toggle via shared `layout.js`, own localStorage key), folder icon link: what waits (files directly in the account folder) as square tiles — preview via `GET /drive/thumb/{id}` (server fetches Drive's `thumbnailLink` with the bot's token; `private, max-age=86400`; 404 = icon instead), video play mark, link to Drive's viewer; nothing waiting = "Nothing waiting to post" (warn); a POSTED line (folder link · Posted today · Last 7 days); extra POSTED folders flagged; the POSTED line sits at the card's bottom (rows align); other subfolders are not shown. Search (`data-search`). `POST /drive/sync` -> `SyncReport` (anyone's Sync, an admin's too, sweeps and reports only their own phones; the background loop does everyone's) (502 with reason when Drive refuses). Not set up / not shared -> notice naming the bot's email. Folders in the root no login owns are listed under a fold (cleanup). Everyone signed in. `drive.js`.
- Data: `devices` (catalog `model_id`/`color_id` or `custom_model`), `logins` (one per service+provider+username, secrets `EncryptedText`, "" stored plain so lists know `has_password` without decrypting), `device_logins` links.
