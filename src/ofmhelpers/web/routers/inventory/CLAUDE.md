- **History and backup (2026-11-14, owner: "every action will have revision ... enforced on db level ... go back to any state").** Table `phone_revisions` (alembic b7c8d9e0f1a3): one row per transaction that touched a person's `devices` / `logins` / `device_logins`, holding all their rows of the three tables after it (`snapshot` JSONB; secrets are the columns' Fernet text). Written by the trigger `phone_revision()` on those tables, so no code path (nine repository methods, cascades, the Drive sweep, psql) can skip it; `phone_revisions_guard()` refuses UPDATE (but the same transaction's upsert), DELETE and TRUNCATE. Unique `(user_id, txid, created_at)`: transaction ids start over in a restored database. The SQL argument is `whose`, not `owner`: `devices` has an `owner` column. `features/phones/revisions.py` `Revisions(scope)`: `GET /phones/revisions` (the History dialog, `_phone_revisions.html`, `phones-history.js`), `POST /phones/revisions/{id}/restoration` (201): one transaction in `db/repositories/phone_revisions.py` -- rows added since deleted, labels and usernames parked (`~<id>`: a swap would trip the unique constraints), the revision's rows upserted by primary key through `jsonb_populate_recordset` (a row that still exists keeps its Drive rows; no decrypting). A column added to a phone table later must have a default, or an older revision no longer restores. The restore is recorded as a new revision. Drive is never touched: accounts that came back are tracked again (`track_login`, revive), their folders made by the next sync; ones that left keep their folder. Tests wipe under `session_replication_role = replica` (root and e2e conftest), which skips the triggers.
- **Backup file** (`features/phones/backup.py`, sweep `phones backup` every `OFM_PHONES_BACKUP_SWEEP_S` 300 s, only with a vault key): the whole History of every owner as one JSON, encrypted whole with `OFM_VAULT_KEY`, `<uploads>/backups/phones/phones-YYYY-MM-DD.json.enc`; written only when the newest revision id differs from `last-revision` next to it; newest `OFM_PHONES_BACKUP_KEEP` 30 files kept. `python -m ofmhelpers.features.phones.backup load <file>` puts back the revisions the table lacks (same person, moment and change = already there), changes no phone.
