# web/routers

## routers/
`routers/__init__.py` `ROUTERS` = the registration list: new page = one import + one entry.

**How a route is written (2026-11-03):**
- Who is asking: typed parameters from `web/dependencies.py` (`user: CurrentUser`, `actor: Actor`, `owner_id: OwnerId`, `scope: Scope`, `assets_root: AssetsRoot`, `api_keys: ApiKeys`). Never `AuthMiddleware.scope(request)` in a route. Helpers take plain values, not the request.
- Who may open it: every router names its area, `APIRouter(dependencies=[Access(Area.X)])`. A route fewer roles may use adds `dependencies=[Can(Action.Y)]`. Which role has which area and action is one map, `schemas/access.py`; a refused role gets 403 `Not available to you`. `tests/unit/architecture/test_access.py` fails on a route that is neither public nor names an area.
- A form of 3+ fields, or shared by routes: `form: Annotated[XForm, Form()]`, `class XForm(FormModel)` in the router (`web/forms.py`; `PaidForm` adds `api_key` + `provider`). 1-2 fields stay `Annotated[str, Form()]`.
- Measured on FastAPI 0.143.3, against its docs: a form model next to a separate `File()` param is 422 `body.form: Field required` whatever is sent, so files go inside the model (`image: Files`); a form model keeps a blank field as "", so `FormModel` drops exact "" (spaces stay a value: a paid `batch` of spaces must stay a 422, not lose the pay-twice guard).
- A refusal worded for the page stays an `HTTPException` in the route or a feature error. Not a validator: that answers 422, and `generation.js` shows a non-string `detail` as "[object Object]".
- A feature's refusal: one row in `web/exceptions.py` `REFUSALS`, no try/except per route. Only errors worded for the person. A feature with no error class of its own raises one of `features/refusals.py` (2026-11-11): `RefusedError` 400 (its optional `detail` model is the answer's `detail` in place of the sentence: /clone-links' refused paste), `ForbiddenError` 403, `NotFoundError` 404, `ConflictError` 409, `UnavailableError` 502 (an outside service failed: our sentence, its error logged), `TryAgainError` 503. A vault problem is not one: `features/phones/service.py` re-raises the store's `VaultError` as its own `SecretsUnreadableError` where a secret is read or written on purpose (no router imports `db`), and `phones.py` puts `_vault_reason` (500 with the reason) on the routes that use a secret, because on the whole router the list page answered raw JSON and lost its crash log.
- 422s never carry `input` (`exceptions.invalid_request`): FastAPI's default echoes the whole form on a missing field, API key included.
- Gallery: `gallery = Gallery({TASK})` (`web/gallery.py`), `query: GalleryParams` + `gallery.page(viewer, query)` on the page and on `/gallery`, `gallery.page(viewer, query.newest())` on `/gallery/latest` (`viewer: Viewing`: the reader's own jobs and their VAs'). **Date filter (2026-11-12, /generate, /clone, /download-assets):** `GalleryQuery` also takes `?date_from=&date_to=` (not `from` / `to`: /clone's `?from=` is where "Clone it" on /edit came from; ISO days, both included, either alone, swapped if reversed, a blank one ignored) read as days of the reader's `ofm_timezone` (`GalleryParams` = the `Query()` model + the `Cookie()`, one function dependency `gallery_query`); `GalleryQuery.created` -> `schemas.persistence.Created` (since/until timestamps) -> `gallery_page(created=)` -> `JobRepository._page_filter` (`created_at >= since AND < until`, index `ix_jobs_user_id_created_at`; total counted inside the filter, so the scroll ends there). The page passes `dates=query`: `_gallery_hidden.html` draws `ui.date_range` at the left of the toolbar row and the page's `data-gallery-endpoint` / `data-live-endpoint` end in `{{ dates.dates }}`, so gallery-scroll.js, hidden-cards.js and live-gallery.js stay inside the filter. A new gallery page gets it by taking `query` in its page route, passing `dates=query` and loading `autosubmit.js`. A plain object, not a class dependency (the FastAPI skill: avoid those). It shows shown jobs only: a page listing hidden ones too keeps `list_jobs_page`.
- One or two routes: a path param stays on the route and the lookup is a plain call (`preset = _visible(preset_id, owner_id)`): behind a dependency alias, ruff FAST003 fails and the id leaves the trace's arguments. 3+ routes repeating the same lookup: one dependency, FAST003 off for that file (owner 2026-11-11: "use Depends", `.claude/rules/routers.md`). The first: `video_tools/trials.py`, where all eleven folder routes took the same `user.id, scope, login_id` + queues -- one dependency `Trials` (`features.trials.folder.Trials`, a frozen dataclass whose methods are the routes' work) builds it once; FAST003 is off for that file in pyproject, and the login is still in the span's `http.route`/URL. Its six per-reel routes take `Reel` (`features.trials.folder.Reel`: the folder + the `key` in the path; a key the folder lacks is the method's 404, `No such reel` / `Not generated yet`). Since 2026-11-11 also `inventory/phones.py` (`Phone`, `Login` = `features.phones.service.Phone` / `SavedLogin`), `admin/users.py` (`OtherUser`), `admin/file_manager.py` (`Asset`; `DiskFile` reads query parameters).
- Telemetry shows an argument's value only for an allowed name holding a plain value, and reads a `LoggedFields` model (a form, a gallery's query) field by field (`telemetry._logged_arguments`): a dependency's result never reaches Logfire, whatever it is called.
- `start_job` adds `job_id` to the run's kwargs: not for a worker function that does not take it.
- A page's template context comes from the feature as ONE model (`FormView` / `PageView` / `ListView` in `features/<page>/page.py` or `service.py`), spread into `render(..., **dict(view))`: `dict(model)` keeps each field's own object, so the template reads what it read before. A field's type is exactly what the template got (an `int` setting typed `float` would print `55.0`). A submit: the route's form model goes to the feature whole, typed there as a `Protocol` (`Submitted`); a worker function (`run_clone`, `run_clone_link`, `run_picture`, ...) lives in its feature since 2026-11-11 (`features/clone/run.py`, `features/clone_links/job.py`, `features/pictures/service.py`, `features/viral/page.py`, `features/uniqify/service.py`, `features/edit/service.py`, `features/generate/service.py`); the router re-imports it under its old name because jobs queued before name that path (`tests/unit/web/test_import_surface.py` `QUEUED_PATHS`), and still hands it to the feature's submit as an argument (`Submit`, `Generate`, `service.start(form, run_picture, ...)`). What recovery does with a task: `features/jobs/registry.py`; `routers/registry.py` keeps labels and routers (`TOOLS`).
- No router imports `ofmhelpers.db` or `ofmhelpers.integrations` (2026-11-11, `baseline.json` `router_imports` is empty): a route calls one function of `features/<page>/` (`account`, `users`, `cookies`, `applications`, `legal`, `uniqify`, `viral/page.py`, `drive/page.py`, `links/self_page.py`, `jobs/own.py` + `jobs/audit.py`, `generate/hosted.py` + `generate/callbacks.py`, `signin/`). A page that answers a write by showing itself again (/account, /users, /cookies) gets that from the feature as a model (`Notice` / `Shown`: message or error + status), never by catching a store's error in the route.
- Status codes (2026-11-11, callers checked: every page script reads `response.ok` or a 2xx range, none compares with 200): a job start answers `202` (`POST /<prefix>/run` of every tool, `/edit/cut`, `/links/generate`), a create `201` (`/phones/add`, `/phones/{id}/logins`, `/pictures/presets`, `/reels/groups`, `/edit/upload`). Left at 200: a POST that may start nothing (/trials' `Started`, `/links/adult|delete|sync`, `/accounts/sync`, `/clone/drive-upload`, `/reels/watch`), a form that answers a page or a 303, and the provider callbacks under `/events`.
- Work a person starts has a job row (2026-11-11, `.claude/rules/jobs.md`): `links_create` / `links_adult` / `links_delete` (`features/links/page.py`), `reels_unlock` (a cookies upload, `features/cookies/service.py`), `drive_upload` (/clone's Upload to Drive), `clone_links_review` (one row per try of an AI check), `report_ask` (a word typed to the Telegram bot: the row keeps the word, never the chat). Their worker functions take no `job_id`, so they start as `create_job` + `enqueue(run_job, ...)` like /trials and /character-sheet. None has a tool in `registry.TOOLS`: the action log lists them without a link, no gallery shows them, recovery fails a cut-off one as interrupted. Bare queue calls left (system work, no person waits): the sweeps' `scan_accounts`, `sync_links`, `scan_all`, the preview backfill's `warm_previews`, the sign-in's `drive_folders.sync`.
- Every route has a return type (`-> Response` for pages, redirects and files, the model for JSON; `test_request_shapes.py` fails otherwise).
- Against the FastAPI skill, measured on 0.143.3: a route that streams by `yield` answers a refusal raised before its first yield as `200` with an empty body, so `/clone-links/previews` keeps returning a `StreamingResponse` (its no-Drive, bad-paste and unknown-resolution refusals must stay 400s; pinned in `test_request_shapes.py`).
