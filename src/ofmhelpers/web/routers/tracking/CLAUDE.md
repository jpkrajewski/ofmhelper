# web/routers/tracking

### tracking/
- `accounts.py` — `/accounts`: KPI cards (total followers, period views, unreachable count) + table (account w/ blue verified badge, followers, growth, views vs previous period, creator tag, phone = drawing + owner of each active /phones phone holding that login via `stores.devices.phones_by_account`, linking to its card `/phones#phone-<id>`; replaced the typed notes column 2026-10-21), default sort followers; header click sorts, clicking the current one flips `order`. Controls: instant JS search over rendered rows (`data-search`), period select (`?period=`), creator select, **Sync** (2026-11-07: `POST /accounts/sync` -> `tracker.sync_now`: every own account due now except one claimed within `claim_ttl_s` (queued/running: a double click or a sweep in progress queues nothing twice), then `queue_due_scans`; rows claimed show " · syncing…" + `data-syncing` (`TrackedAccount.syncing` from `claimed_at`, set by the store), and both pages reload every 8 s while any `[data-syncing]` is shown; the button itself is rendered disabled "Syncing…" with `data-syncing` while any own account syncs, filtered out or not -- 40 clicks on dev 2026-11-07 queued 1 sync, but the button looked clickable). The "Synced without an Instagram login" banner shows only to a user with no cookies saved (`_ask_for_cookies`: logins are the scans' last resort, uploading again changes nothing). Scans go through the sources (integrations/socials/CLAUDE.md: Apify, proxies, login). No status/platform filters or badges in the UI (backend still accepts `platform`/`status`); private/failed-sync rows are red (`data-problem`, reason as tooltip). Creator is assigned from the selection card above the table (shown only while rows are picked) or the Add dialog, never inline. All state in `schemas.AccountQuery` (blank params = unset; `link()`/`sort_link()`). JSON posts `/accounts/add`, `/creator`, `/delete` (bulk ids), `/{id}/notes` (stored notes kept; no UI since the Phone column). `/accounts/{id}`: identity left, period select + Assign link right in one `.toolbar-actions` row, 4 KPIs, daily follower line, every post of the period by views (thumbnail, "N h/d ago", `<progress>` bar). Banner when accounts were synced without a working Instagram login (`metrics.limited`). Metric rules: 0 = confirmed zero, dash = no data, comparison blank when unknown; growth % only with a non-zero baseline. Phone: rows become cards. `accounts.js` serves both pages.

- `links.py` — `/links`: KPI cards (clicks + CTR, views, per provider quota `used / limit` + active), notices (no key -> /account, last sync error, plan full, links without 18+), filters (period 1/7/30/90 d, provider, model, `?account=`), table (link + copy, provider, status badges Making…/Deleting…/Failed/Inactive/No 18+, Instagram account -> its analytics, target, model, views, clicks, CTR; failed rows red with the error as title), selection card (Copy links, Assign model (existing creators only), Turn on 18+, Delete on provider with confirm), Sync, Generate links dialog (model, provider, domain, target, target link, the model's Instagram accounts pre-picked). State in `schemas.LinkQuery`. `links.js` polls while rows are creating/deleting. /accounts has a `Links · period` column (provider · clicks · CTR, -> `/links?account=`).
