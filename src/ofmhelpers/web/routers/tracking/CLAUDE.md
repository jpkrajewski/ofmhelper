# web/routers/tracking

### tracking/
- `accounts.py` — `/accounts`: table with phone = each active /phones phone holding that login (`stores.devices.phones_by_account`, links to `/phones#phone-<id>`). **Sync** (`POST /accounts/sync` -> `tracker.sync_now`: every own account due now except one claimed within `claim_ttl_s`, so a double click or a sweep in progress queues nothing twice; claimed rows show `data-syncing` (`TrackedAccount.syncing` from `claimed_at`) and both pages reload every 8 s while any is shown; the button is disabled "Syncing…" while any own account syncs, filtered out or not -- 40 clicks on dev 2026-11-07 queued 1 sync, but the button looked clickable). The "Synced without an Instagram login" banner shows only to a user with no cookies saved (`_ask_for_cookies`: logins are the scans' last resort, uploading again changes nothing). Scans go through the sources (integrations/socials/CLAUDE.md: Apify, proxies, login). No status/platform filters or badges in the UI (backend still accepts `platform`/`status`). Creator is assigned from the selection card or the Add dialog, never inline. All state in `schemas.AccountQuery` (blank params = unset). `/{id}/notes` has no UI (stored notes kept). Metric rules: 0 = confirmed zero, dash = no data, comparison blank when unknown; growth % only with a non-zero baseline. Phone: rows become cards. `accounts.js` serves both pages.

- `links.py` — `/links`: Assign model takes existing creators only. State in `schemas.LinkQuery`. `links.js` polls while rows are creating/deleting. /accounts has a `Links · period` column (-> `/links?account=`).
