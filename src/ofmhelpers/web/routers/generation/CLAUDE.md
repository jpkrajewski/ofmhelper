# web/routers/generation

### generation/
- Every generation page (/generate, /clone, /clone-links, /clone-long, /pictures) starts on the provider of the person's LAST run there (`features/generate/providers.start_provider`, `stores.jobs.last_param`; the three clone pages share `CLONE_TASKS`), if the page offers it; else `settings.aigen.default_provider` (`OFM_DEFAULT_PROVIDER`, default `higgsfield`) if offered; else the page's first. Last, not most (owner 2026-11-10 "dynamic default based on usage"; prod that day: /clone 362 Higgsfield runs vs 62 APIYI, all of that day's on APIYI).
- `index.py` — `/generate`: provider -> model -> fields (`ai-form.js` loads `GET /ai/fields`), cross-provider gallery with Recreate, paged via `gallery-scroll.js` (no sentinel = end). Tasks: `registry.GENERATE_TOOLS`.
- `ai.py` + package `features/generate/` — `/ai`: fields rendered from the spec; `/ai/run` -> `service.prepare_run` parses + `spec.check`s before upload/payment (400 names the field), batch capped by `OFM_AIGEN_MAX_BATCH`. Key goes to the worker only. Router = routes + thin `run_ai` (the path RQ stores); `service.run_ai`: upload refs, `runner.generate`, register results.
- `legacy.py` — job routes of old per-model routers (table: `features/generate/legacy_tools.json`), no `/run`. `as_ai_params` (`Tool.form_params`, applied in `registry.task_card`) gives their cards `provider`/`model` + schema field names (seedream5, nanobanana, gpt_image, wan3), else Recreate restores only the prompt.
- `clone.py` + package `features/clone/` — `/clone`: 1..`clone_max_images` subject images + N videos -> one Wan 3.0 job per video. Router = routes + thin entry points (`_run_clone` for RQ; `run_ai`, `duration_s`, `_exported` looked up there). `features/clone/`: `targets.json` (Wan 3.0 table, new provider = one row; /clone-long takes rows with `long_clone`), `pricing.py`, `service.py`, `export.py`. Params provider-neutral. Duration = video length clamped to the schema. All videos probed and runs checked before queuing; `clone_max_videos` caps a submit. No batches (2026-10-22): each run is its own card (`_clone_card.html`, extends `_gallery_card.html`), newest first, paged/live like /generate (`/clone/gallery`, `/clone/gallery/latest`); a submit's cards come back rendered and go in place (`clone.js`). Meta line = export label only; no timers/ETA (`clone_eta.py` removed). Recreate = that card's images + its one video + settings. Upload to Drive (card ⋯ menu) opens the picker dialog: account folders (`drive_uploads.targets`: handle, owner, model = the account's /accounts creator, files waiting unposted from the last /drive read, followers) sorted empty-first then most followed, search + model filter, folders the video is already in marked, several at once (`UploadRequest.login_ids`); rows show followers + owner; nothing pre-checked (a remembered pick sent one video to two accounts, 2026-10-22), only the model filter is remembered.
  - One-click picks (2026-11-06, from prod's 393 runs; `clone-picks.js`): Subject shows "Last used" (5) then "Most used" (5) subjects = a run's FIRST image (Image2 is often the clothes picture), from /clone + /clone-links runs, grouped by content hash (`<sha256>__<name>`: 44 stored paths were 36 pictures), a picture in both rows allowed (user decision), only ones still in the store (another stored name of the same hash counts; `features/clone/service.subject_picks`, `OFM_CLONE_LAST_SUBJECTS` / `OFM_CLONE_TOP_SUBJECTS`); a click makes it THE subject (list replaced, never added: user decision). Prompt add-on chips under the prompt (`features/clone/addons.json`, ordered by prod use: same clothes as @Video1 58, remove text overlay 55, no tattoos 41, clothes from @Image2 19, reflections 10, jewelry 7, face 7; Hairy body added 2026-11-10 after clothes from @Image2: 10 clone runs asked "make his body as hairy as possible" / "hairy chest", image prompts "very very hairy chest and stomach"; its text has no comma, so an un-press takes all of it): click appends ", <text>", a pressed chip (its `pattern` matches any wording, "NO TATTOS") takes out every comma/line piece asking for it, never the first. Start opens `#clone-confirm`: subject images, the prompt as sent, the `check` add-ons (what same-video re-runs most often added: clothes 7, tattoos 4, jewelry 4, text overlay 3) + Audio as the same chips, `Start · $cost` / Cancel; the form is read after the dialog.
  - Export: one dropdown from `ofmhelpers.media.exports` (Original, CapCut — default `OFM_EXPORT_DEFAULT`, one entry per `iphones/` profile) + Mirror switch (`ExportOptions`, start state `OFM_EXPORT_MIRROR`), stored as job `mirror`. The exported copy becomes the result; the provider's raw file never is (user rule 2026-10-25): an export is tried `OFM_EXPORT_ATTEMPTS` (3) times, then the run fails "Export failed" keeping its paid request, and recovery re-runs it (resumed, unpaid) up to `OFM_EXPORT_RERUNS` (3) runs. Old jobs' `capcut` bool maps to `capcut`/`original`.
  - Cost panel (`clone-cost.js`): length x credits/s x $/credit per provider (`clone_pricing()`), per second of source video (2026-11-02, 720P): kie.ai $0.16, Higgsfield $0.433 (measured: $29 / 67 s on the new key), RunningHub $0.14, Elyum $0.1584 (RunningHub and Elyum in USD: `unit` "USD", $/credit 1); kie.ai, RunningHub and Elyum bill clip + output seconds. `CloneTarget.max_reference_s` (Wan 3.0: 15 s, every provider). Longer videos flagged in the panel and rejected at submit (long ones: `/clone-long`). Panel prices the full length and shows the piece count; card meta says `· N pieces`.
- `clone_long.py` + package `features/clone_long/` (2026-10-23) — `/clone-long`: one image + one video of any length (`OFM_CLONE_LONG_MAX_S` 600). No export. Three switches, default off (dev `.env` has all three on), copied into `LongCloneParams` at queue time so a recovery re-run never mixes pieces made under two settings (a job stored before them = all off): `OFM_CLONE_LONG_AUDIO` (each piece asked for sound, kept through the join), `OFM_CLONE_LONG_COLOUR_MATCH` (each piece's mean RGB pulled to piece 0's with `colorchannelmixer` before the join, per channel at most x0.75..x1.33 so a dark piece is never blown white; the copies + the concat listing live in the job's work folder, never the shared output folder), `OFM_CLONE_LONG_CHAIN` (pieces one at a time, piece N gets piece N-1's very last frame (`-sseof -0.2 -update 1`) as a second reference image + prompt "Start video from @Image2"; no parallelism, so the RQ limit has a provider wait per piece: Higgsfield takes ~4.5 min per 14 s 480P piece, an 8-piece run took 42 min on dev 2026-10-27). A piece is asked for `round(seconds)` (`Target.duration`), so the clone can come out shorter than the source (100.7 s in, 99.2 s out, 2026-10-27). `models.py` (`Plan.split`: fewest near-equal whole-second pieces of <= 15 s; `Shape`; `Rate.quote`; `LongCloneParams` = job params, no key), `video.py` (`VideoTools`: length, shape incl. rotation, cut, last_frame, join), `service.py` (`Target` per provider, `LongClone.prepare/run/time_limit`, `run_long_clone` = worker + recovery entry). Every piece is its own request (`tasks` part i, idempotency `job:i`, `OFM_CLONE_LONG_PARALLEL` 5 at once) straight through `runner.generate` (not `run_ai`: a piece is no asset and its failed download must stay resumable); a re-run never pays twice. Work folder `<uploads>/.clone-long/<job>`: cut pieces (short side <= `OFM_CLONE_LONG_PIECE_MAX_SIDE` 1080: a 4K source's pieces were full-size re-encodes) + saved results `result_i.mp4` (a re-run skips them, no status/download); removed after the join, on a refusal, a non-`resumable` failure (`stores.jobs.resumable`) or one with no part remembered (wrong key); kept on RQ's time limit (threads may still use it) and for recovery, else dropped by the next run once older than `resume_max_age_s`. The first failure starts no further piece (stop flag checked before cut/submit; a pool thread takes the next piece the instant its own fails), in-flight ones are waited for, a refusal forgets every part. RQ's time limit mid-run: no further piece, pool not waited for. Pieces run in a copy of the job's context (Logfire trace). Gallery paged like /clone (`/clone-long/gallery`, 2026-10-24; was one fixed page). Join = concat demuxer + `-xerror` (the concat filter opened all 40 pieces at once: 2.5 GB at 720p; now 290 MB, 1080p 530 MB / 70 s; without `-xerror` an unreadable piece ends the video early with exit 0). File manager: CLONE section. Shape: each piece asked at Wan's nearest ratio, the join scales/pads to the source's exact aspect at the pieces' height. Price: page previews (`clone-long.js`), `/run` re-measures and stores the server's. RQ limit per run (`Tool.job_timeout`, recovery uses it).
- `clone_links.py` + package `features/clone_links/` (2026-10-25, VA request; hardened after review 08dd2a2 the same day) — `/clone-links`: subject image(s) + pasted reel links -> one /clone run per link (`clone._run_clone`: same provider/export/mirror/audio, params + `link`), each result checked for glitches and uploaded into the clicker's own Drive root: `GOOD REELS` for a GOOD verdict, `TRIAL REELS` for GLITCHY or a check that could not answer (`folders.py`; /drive's "other folders" fold leaves them out).
  - **Check** (`POST /check`, instant) = `links.read_pasted`: one link per line, cleaned (`SourceLink`: trackers/#fragment dropped; Instagram p/tv/reel(s)/<user>/... -> `https://www.instagram.com/reel/<code>/`, TikTok video -> `https://www.tiktok.com/@u/video/<id>`), each once; a link must be ONE post of an extractor in `OFM_CLONE_LINKS_VIDEO_EXTRACTORS` (profile/playlist/story/redirector refused: "Paste a reel's link, not a profile or playlist"; Instagram/Facebook `/share/` links: "Open the link and copy the reel's address"). A bad line refuses the whole paste (400 `CheckRefused`, every line named, modal `#clone-links-refused`, box never split or guessed -- user decision 2026-10-25).
  - **Generate**: Drive must be connected (JS stops first, `data-drive-ready`; `/previews` and `/run` 400 otherwise) -> `POST /previews` streams one `LinkPreview` per link (`preview.py`: yt-dlp read, no download, one post only, Generic never; cached in Redis PER USER; process-wide `PREVIEW_PARALLEL` 6 reads; whole request ends at `PREVIEW_DEADLINE_S` 90 -- late ones "Took too long, try again"; fixed reasons only, raw yt-dlp text in logs; whole-second length at the limit = too long; covers fetched only from public hosts) -> confirm dialog (tiles sort once when the stream ends; Remove; Drive-room warning from the cached `free_mb` x `REEL_MB`) -> `POST /run` with the page's `batch` id: a resend of the same batch returns the runs already queued (SET NX `clone-links:run:<actor>:<batch>` + `list_batch`), so a lost answer never pays twice. Runs go on their own queue `clone-links` (`clone-links-worker`, `OFM_CLONE_LINKS_WORKERS` 5) through the router's thin `run_clone_link` wrapper (a worker must import the routers first).
  - **The run** (`clone_links/run.py`, also recovery's re-run): job row gone -> nothing; stopped batch (`POST /clone-links/stop/{job}`, `clone_links/stop.py`, checked at entry and before paying) or halted batch (a wrong key / no credits stops the rest, `clone-links:halt:<batch>`) -> fails at once unless its request is already paid; download as the owner (`media.downloaded(single=True)`, work dir removed), source kept on the job params so a paid re-run never downloads again (gone + download fails = `ProviderUnavailableError`, stays remembered); over 15 s refused before paying ("Too long for Wan 3.0 ..."); a hosted-only result fetched again. Fixed card texts (`schemas/errors.py`: Could not download, Needs login, Too long, Stopped, Still generating).
  - **Review** (`review.py`, `clone_from_links`: unique per job+file, FK CASCADE to jobs, `path`/`started_at`/`attempts`): `start_reviews` (never raises; a missing local file = failed row "use Download") -> `review_file` (RQ limit `REVIEW_TIMEOUT_S`) claims the row atomically (`started_at`), checks (`clone_ai_check.check_clone`, whole check <= 600 s, a crash = unanswered -> TRIAL), uploads through `drive_folders.review_folder` (per-user lock, folder id remembered; an existing same-named file is adopted). `checked`/`finish` write only while the claim holds. Recovery (`resume_reviews`, every sweep): a claim older than `REVIEW_STALE_S` re-queued (`REVIEW_ATTEMPTS`), failed uploads retried once Drive has room / a working token, done runs with no review row started. Cut-off = from `started_at`; an unclaimed review is waiting, never cut off. No "Check again" (user decision 2026-10-25).
  - **Card** (`_clone_links_card.html` + `_clone_from_link.html`; no source link, no badge/%/model name -- user decisions): Drive line, then "AI decision: good / glitch / not done" (quota: "not done (AI busy or daily limit reached)") opening the problems + reasoning; never raw errors. Recreate: a failed card's brings back the batch's failed links (paste order, hidden ones, still-generating ones and ones redone later left out), a done card's its own. `clone-links.js` polls `/reviews` for unsettled blocks every 4 s in chunks of 100; an open panel stays open; Stop sits after "Queued N runs.".
