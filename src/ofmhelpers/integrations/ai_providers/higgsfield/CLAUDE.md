# integrations/ai_providers/higgsfield

## Higgsfield (`higgsfield/`)
- Official SDK `higgsfield-client` 0.2.0. Key `KEY_ID:KEY_SECRET` (`HF_API_KEY_ADMIN`, admins' default). Uploads only JPEG/PNG/WebP/GIF/WAV/MP4. A .mov/.m4v/.webm/.mkv reference goes up as an MP4 copy (`utils/video_mp4.py`, in `out_dir/higgsfield/mp4`, `OFM_HF_VIDEO_CONVERT_TIMEOUT_S` 900); one ffmpeg cannot read = `ProviderInputError` "Could not turn <name> into an MP4 video" before any call (prod 2026-11-02: an iPhone .mov failed /clone with "Higgsfield takes ... not ...__Video-21956.mov"). BMP/TIFF as a JPEG copy (`fitted`). A cached URL is HEAD-checked before reuse (`OFM_HF_REMOTE_CHECK_TIMEOUT_S`, else kie.ai's variable, which it used to read).
- `catalog.json` generated (83 models) by `scripts/sync_higgsfield_catalog.py`.
- Findings (2026-10-18, docs.higgsfield.ai): base `https://api.higgsfield.ai`, header `Authorization: Key <id>:<secret>`; statuses queued/in_progress/completed/failed/nsfw/canceled; uploads via presigned URL (1 h, PUT without key); outputs kept ≥7 days. Every submit carries `Idempotency-Key` = job key + digest of the body (`_submit_key`, since review #61 2026-10-25); the SDK's transport resends a 408/5xx 3 times under it, and the runner resends a lost answer (`idempotent_submit`) -- docs concepts/idempotency: a repeat "returns the original `request_id` without creating or charging for another generation", even after it ended. SDK transport: no retry on timeouts; request timeout 300 s. Higgsfield also has signed webhooks (Standard Webhooks, `?hf_webhook=`, retried 2 h on 5xx): unused.
