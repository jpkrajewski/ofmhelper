# integrations/ai_providers/runninghub

## RunningHub (`runninghub/`, 2026-10-31)
- Standard Model API (`https://www.runninghub.ai/openapi/v2/*`, docs `https://www.runninghub.ai/runninghub-api-doc-en/llms.txt`, each page `<page>.md` with its OpenAPI): every model is `POST /openapi/v2/<model path>` with a plain JSON body, `Authorization: Bearer <key>`; `POST /openapi/v2/query {"taskId"}` -> `status` CREATE/QUEUED/RUNNING (pending), SUCCESS (`results[].url`), FAILED/CANCEL, `usage.consumeMoney`; upload `POST /openapi/v2/media/upload/binary` (multipart `file`) -> `data.download_url`, signed for 24 h (cached per account + path for `OFM_RH_UPLOAD_CACHE_TTL_S`, 20 h, one upload per file across workers). The ComfyUI workflow / AI app API (`/task/openapi/*`) is not used.
- HTTP 200 with the code in the body (`errorCode` string on tasks, `code` on uploads); `models.raise_for` maps the docs' table: auth 412/435/436/801/802/806/811/1002/1014/1602 (1014: the model API takes **Enterprise-Shared keys only**), no balance 416/812 (`ProviderNoCreditsError`, also on a FAILED task: `TaskState.no_credits`), rate/concurrency 415/421/814/1003/1011/1520 (`ProviderRateLimitError`, nothing created), content 1501/1505 ("Photorealistic real people are prohibited": `ProviderGenerationError`, card "Flagged content"), transient 500/808/1000/1005/1006/1010/1012/1015/1504/1517/1519, else input. A wrong key's upload answers code 1 "ApiKey verification failed".
- **No idempotency key**: a submit is sent once, never retried by the client (the runner resends only on a rate-limit refusal); our job id only goes into the submit log line.
- `catalog.json` — 324 models (225 video, 99 image), generated by `scripts/sync_runninghub_catalog.py` (reuses the kie.ai script's OpenAPI cleaning): model id = the path after `/openapi/v2/`; the docs' example values are not defaults (dropped on prompts and media fields: sample asset URLs); camelCase `...Url(s)` fields get `x-media`; a string enum of whole seconds (`duration` "auto","2".."30") becomes an integer range marked `x-wire: string`. `provider.wire_body` sends every schema default the payload left out (RunningHub requires `aspectRatio` etc.) and `x-wire: string` fields as strings. Audio/3D/Other pages and 4 models with fields the form cannot fill are skipped.
- /clone: `CLONE_TARGETS["runninghub"]` = `alibaba/wan-3.0/reference-to-video` (`imageUrls`, `videoUrls`, `audio`, `aspectRatio`; billed output + min(reference, 15) s). The cost panel uses $0.07 per billed second at 720P (user's account, 2026-11-02) in dollars per source second (`OFM_CLONE_RH_USD_PER_VIDEO_S`; `POST /openapi/v2/price-preview/<model path>` with a key answers an exact one). Motion-transfer models also there: `rhart-video/wan2.2/character-motion-transfer`, `kling-v3.0-pro/motion-control`.
- Key `RUNNINGHUB_API_KEY_ADMIN` (admins' default), `OFM_RH_BASE_URL` (runninghub.cn is a separate site and account). Fake `runninghub/fake.py` (`FAKE_KEY`, `refuse_next`, `fail_next`); tests `tests/integration/aigenproviders/runninghub/`, contract `tests/contract/test_ai_provider_contract.py`.
- Unverified until a real key runs: whether a failed task is billed, how long result URLs live (downloaded at once), real-person handling on Wan 3.0 (1505).
