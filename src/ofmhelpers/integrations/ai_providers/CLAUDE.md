# integrations/ai_providers

AI providers behind one interface; every model is catalog data. The /ai form, runner and recovery never name a provider or model field; /clone and /pictures keep one row per provider.
Providers: kie.ai (`kie/`), Higgsfield (`higgsfield/`), RunningHub (`runninghub/`), Elyum (`elyum/`), APIYI (`apiyi/`), fake (`fake/`, free, for tests/pages).

/clone cost panel (`clone.clone_pricing`, 2026-11-02, per second of SOURCE video at 720P): kie.ai $0.16 (16 credits/billed s, billed = clip + output), Higgsfield $0.433 (measured: the key saved 2026-11-02 paid $29 for 7 runs / 67 s; its old 60% discount is gone), RunningHub $0.14 ($0.07/billed s), Elyum $0.1584 ($0.0792/billed s), APIYI $0.1176 ($0.0588/billed s, 2026-11-06). 480P/1080P half/double.

## Shared layer
- `base.py` — `Provider`: `upload`, `submit(spec, payload, idempotency_key)`, `status -> TaskState`, `download`, `default_key()` (the admin's .env key; users only their own); class vars `name`/`label`/`rank`/`needs_key`. `@register_provider` into an `lru_cache`d registry; lookups `provider_class`, `get_provider`, `provider_names`.
- `spec.py` — `ModelSpec` (one catalog entry, `key = "<provider>:<model id>"`). Derives `media_fields`, `form_fields`, `parse_form`, `check` (jsonschema 2020-12, before any upload/payment), `request`. `max_upload_bytes`: a model's own documented per-file limit above its provider's default cap (kie.ai `nano-banana-pro`: 30 MB, docs.kie.ai market/google/pro-image-to-image); `base.uploader(provider, spec)` hands it to `Provider.upload(path, max_bytes)`, so a reference under it goes up as the original file instead of a JPEG copy (user rule 2026-11-01: best-quality input). Every provider's upload cache key carries the limit, so a copy cached under the default cap is never reused. Measured on kie.ai 2026-11-01 (real runs, files sent raw): Nano Banana Pro took a 29.2 MB and a 32.1 MB PNG and a 10000x10000 px PNG (limit set to the documented 30 MB; the 8000 px side cap still applies to it); Wan 3.0 took a 19.5 MB image and an 8000 px side, refused 21.1 MB (422 "file size exceeds limit": limit 20 MB), refused a 127.5 MB video (422) and a 4320 px wide video (422 "resolution is out of range"), and failed a 104.3 MB one after submit ("Internal Error"): videos stay originals, so one over 100 MB or 4096 px fails on kie.ai. Higgsfield Wan 3.0 reference-to-video took 19.5 MB, 21.1 MB and 8000 px images (limit set to the proven 21 MB; its true ceiling is untested above that).
- `catalog.py` — `catalog()`, `get_spec(key)`, `models_for(provider, kind)`.
- `self_heal.py` — **the one self-heal module, for every provider** (prod 2026-11-05: kie.ai made and billed a Wan 3.0 clip 2 s after our createTask gave up; it showed only on kie.ai's Logs page; user rule: nobody ever checks a provider's site). The runner sends every new request through `new_task` and every result download through `download`; a provider only declares on `Provider` how a lost submit is found again, nothing in the module names one:
  - `idempotent_submit` (Higgsfield, Elyum): a submit with no answer is resent under the same key (waits `OFM_AIGEN_RATE_LIMIT_WAITS_S` 10/30/60 s +0-25%, at most `OFM_AIGEN_RATE_LIMIT_MAX_WAIT_S` 180). Elyum: a resend after the render ended is 409 `idempotency_conflict`, so a lost answer heals only while the resends last (~3 min); Higgsfield replays even after the end.
  - `callback_url(job_key)` + `callback_task_id(raw, headers)` + `callback_signed()` (kie.ai: `callBackUrl` = `<APP_BASE_URL>events/ai/kie/<job>[:<part>]`, only when APP_BASE_URL is https, so never on dev): the submit is noted first (`tasks.remember_sent`, Redis `aigen:sent:<job>:<part>`, not swept by recovery); a lost answer keeps the job running while `_await_callback` waits up to a generation's poll timeout from when it was sent; `heard` (route `POST /events/ai/{provider}/{job_key}`, `web/routers/webhooks.py`) takes a signed callback as is, checks an unsigned one with the job's key (a made-up id is not on our account; a provider too slow to say is taken, the run's poll checks it) and `tasks.found` remembers the task. A genuine callback is never answered with an error (kie.ai's Veo page: 3 tries, then none). No callback in time = the job fails "Timed out", the note stays, and a later callback hands the task to recovery (re-run, resumed, never paid twice). A noted submit is never sent again: a re-run waits for its callback (`_lost_task`), recovery does not re-run a job with one (`tasks.waiting`, outcome "waiting": a long clone would pay a piece twice), `tasks.forget` drops the notes (a refused long clone must not come back on a late callback).
  - neither (RunningHub, APIYI: no idempotency key, no webhook, no task list; RunningHub's model API -- only `POST /openapi/v2/query` by task id; webhooks exist only on its ComfyUI/AI App API, docs checked 2026-11-05): never resent, never paid twice; a lost answer past its 300 s wait is lost.
  - every provider: a rate-limited submit is resent (nothing made); a submit that never left (connect timeout / refused / DNS: `ProviderUnavailableError.maybe_made` False, `http._never_sent`, Higgsfield `httpx.ConnectError`) fails at once; a result download failing with `ProviderUnavailableError` is tried again after each `OFM_AIGEN_DOWNLOAD_RETRY_WAITS_S` (5/15 s; review #11: one CDN blip cost a paid file). Every wait goes through `self_heal._sleep` (tests patch it). Review 2026-11-05 (a fresh agent; fixed the same day) and its proof on dev: the real lost job 5e57aa92 healed from its real task id, 0 credits; kie.ai's real (signed) callback through a tunnel, 1.6 credits.
- `runner.py` — `generate(...)`: resume (`tasks.recall`) or `self_heal.new_task`, poll with backoff, `self_heal.download` to `settings.aigen.out_dir`. Timeout leaves the request remembered for recovery; other errors (disk full) raised at once, the request stays remembered either way. The poll keeps `time.sleep`.
- `TaskState.no_credits` — a request accepted, then failed for want of credits: the runner raises `ProviderNoCreditsError` (card "No credits", a /clone-links batch halts), not `ProviderGenerationError`. Higgsfield sets it from a `failed` status whose error says "credit balance" (prod 2026-10-31: "Your credit balance is too low to complete this request. Please top up your balance and try again." -- three /clone runs showed "Failed").
- `tasks.py` — `ProviderTask` per job in Redis (`aigen:task:<job id>`), incl. the key it was made with. Redis errors logged, never raised.
- `errors.py` — `InvalidInputError` + `ProviderError` family (auth/input/generation/unavailable/timeout) + `ProviderNoCreditsError(ProviderInputError)` (empty balance: a batch stops asking) + `ProviderRateLimitError(ProviderUnavailableError)` (`.retry_after_s`; only for "nothing created", never a 5xx/timeout). Adapters map codes onto these -- including answers they cannot parse (non-JSON 200, wrong shape): `ProviderUnavailableError`, so a paid request is polled again and stays resumable instead of a ValueError that makes `run_job` forget it (review #56). A rejected key is always `ProviderAuthError(label, detail)` = "<label>: wrong API key" (provider text in `.detail` + exception note, for logs).
- `base.upload_lock(cache_key)` — one upload per file across worker processes (Redis lock `lock:<cache_key>`, `OFM_UPLOAD_LOCK_S`); Redis down (lock creation or acquire) = no lock, upload anyway; a lock lost mid-upload = release warning only. `cache_key` is logged, so it never carries an API key (`upload_cache_key` hashes it).
- `hosting.py` — this server as the file host of a provider with no upload endpoint (APIYI): `link(path, label, reuse_s)` = `<OFM_AIGEN_PUBLIC_BASE_URL or APP_BASE_URL>/files/ai/<token>/ref<suffix>` (never the file's own name); token = 32 random bytes, Redis `aigen:hosted:<token>` -> the file's path for `OFM_AIGEN_HOSTED_TTL_S` (3 h: the provider fetches when its task starts, a resumed task needs no reference again; one fetch is not "done": a video is HEAD + ranged GETs + retries, and one subject image serves a whole batch); the same file keeps its link for at most half that, per public address (`memoized`, liveness = same address + the token still resolves: a new dev tunnel never gets a dead address's link). Served by `web/routers/ai_files.py` (GET + HEAD, ranges, `private, no-store`, `nosniff`; public: `/files/ai/` in `public_prefixes`, checked absent from both servers' .env overrides 2026-11-06; unknown/expired/malformed token or a file gone = 404). The token is never logged by us (`hosted_file` reads Redis itself; nginx and Logfire still see request paths: 3 h life). Base not https (localhost dev) = `ProviderInputError` before anything is paid; dev runs with references through a tunnel's address in `OFM_AIGEN_PUBLIC_BASE_URL`. Redis down = `ProviderUnavailableError(maybe_made=False)` (a link that would 404 is never handed out).
- `uploads.py` — `upload_cache_key(prefix, api_key, path, max_bytes)` (`<prefix>:upload:<sha256(key)[:16]>:<path>[:<max_bytes>]`), `memoized(cache_key, ttl_s, upload, live=None)` (lock, Redis lookup, optional liveness check, upload, remember), `remote_file_exists(url, timeout_s)` (HEAD, fails closed), `reference_copy(path, folder, limits, convert_timeout_s, takes)` (MP4/JPEG copy of what the provider does not take; the caller words its errors).
- `http.py` — for a provider without an SDK: `bearer_session(key)`, `call(session, label, refused, method, url, **kwargs)` (unreachable = `ProviderUnavailableError`, HTTP error = the provider's `refused`), `parsed(response, model, label)` (unreadable 2xx = `ProviderUnavailableError`), `Lenient` (base of every wire model). Nothing here retries: a resent POST pays twice.

## Adding a provider
In `<name>/`:
1. `provider.py` (`@register_provider`; map statuses to `TaskState`; how a lost submit is found again, for `self_heal.py`: `idempotent_submit = True` if a resend with the same key answers the request already made, else `callback_url` + `callback_task_id` (+ `callback_signed`) if it calls back -- read its docs for both before writing anything; transport errors set `maybe_made=False` when no connection was made), `models.py` (wire format on `http.Lenient`; failures mapped to `errors.py`), `client.py` on `http.py` + `uploads.py`, only without an official SDK. No upload endpoint: `upload` returns `hosting.link(...)` (APIYI).
2. `catalog.json`: `{model_id, label, family, kind, input_schema[, fixed, default_prompt]}`; generate it if the provider publishes schemas (`scripts/sync_<name>_catalog.py`).
3. `fake.py`: the provider's wire faked for OFM_FAKE_EXTERNALS, one `FAKE_KEY` accepted.

Outside it, today:
4. `config/settings.py`: a `ProviderSettings` group (`env_prefix`, admin key var, `base_url`, `upload_cache_ttl_s`); `config/__init__.py`: its property + import; `config/CLAUDE.md`: one line.
5. `utils/outbound.py` `_routes`: the fake's routes (requests only; an SDK on httpx gets a `MockTransport` from `fake.install` instead).
6. `redact.py` `_KEY_SHAPES`: the key's shape, if it has a recognisable one.
7. Tests: wire-level faked tests in `tests/integration/aigenproviders/<name>/`; `tests/contract/test_ai_provider_contract.py` `PROVIDERS` and `tests/contract/conftest.py` `_REAL_SETTINGS`.
8. To offer it there: /clone = a row in `features/clone/targets.json` + its price in `WebSettings`; /pictures = a `PictureTarget` in `web/routers/image_tools/pictures.py`.

## Fakes (OFM_FAKE_EXTERNALS)
- `kie/fake.py` — upload/createTask/recordInfo/result host; `FAKE_KEY` only (else code 401); "generating" for 2 polls, then success.
- `higgsfield/fake.py` — `install(client)` puts an httpx `MockTransport` under the SDK (its `_client`/`_upload_client` cached properties, higgsfield-client 0.2.0); `FAKE_KEY` only (else 401); queued 2 polls, then completed; result/upload host served to `requests` too.
- `base.Provider.download` goes through `utils/outbound.get`.
- Wire behaviour (success after 3 polls, 4xx, 5xx, timeout, maintenance, rate limit resent then paid once / persisting, unreadable answers stay remembered, result download retried, failed, rerun resumes, never resubmits otherwise): `tests/integration/aigenproviders/test_provider_wire_behaviour.py`, bodies in `tests/fixtures/providers/`; runner logic against an in-memory provider: `test_runner.py`.
