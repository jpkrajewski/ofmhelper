# integrations/ai_providers/kie

## kie.ai (`kie/`)
- `client.py` — the transport retries GET/HEAD only (a createTask is never resent by it — paid twice); createTask waits `OFM_KIEAI_CREATE_TIMEOUT_S` (180), the status read `OFM_KIEAI_REQUEST_TIMEOUT_S` (30): Wan 3.0's createTask answers once kie.ai has the references, 1-3 s usually, 17.5 s and >30 s on prod 2026-11-05 (the second failed the job "kie.ai unreachable: ReadTimeout"; kie.ai made that task 2 s after we gave up and billed 288 credits -- found only on kie.ai's Logs page, healed on dev from its id: see "Lost submit answers" above); the runner resends a createTask only on code 429 (docs.kie.ai: "Rejected requests will not enter the queue"). Errors via `models.raise_for` (401/403 auth, 402 `ProviderNoCreditsError`, 429 `ProviderRateLimitError` (HTTP Retry-After read when present; in-body has none), 408/455/5xx `ProviderUnavailableError` (455 maintenance is not resent), else input). An answer that is not JSON or not the model's shape (`http.parsed`), or a SUCCESS whose `resultJson` cannot be read (`KieProvider._result_urls`), is `ProviderUnavailableError` "unreadable". Audit trail = log events (`kie.ai task created` / `kie.ai task completed`, with task id, job id, credits: stdout and Logfire); the `tasks.jsonl` / `completions.jsonl` files it appended to until 2026-11-11 were read by nothing and are no longer written (the old ones stay in `./kieai_out` on the server). Upload memo in Redis keyed `kieai:upload:<sha256(key)[:16]>:<path>` (`uploads.upload_cache_key`; the raw key was in Redis key names and lock warnings until review #27), HEAD-checked; oversized images uploaded as a shrunk JPEG copy.
- Key `KIE_AI_API_KEY_ADMIN` (admins' default). No idempotency key; re-runs resume.
- `callback.py` — kie.ai's callback (docs.kie.ai market pages: POST `{code, msg, data: {taskId, state, resultJson, creditsConsumed, ...}}` when a task ends; retries undocumented). Signature (docs common-api/webhook-verification): `X-Webhook-Timestamp` + `X-Webhook-Signature` = base64 HMAC-SHA256(`<taskId>.<timestamp>`, webhookHmacKey from kie.ai's Settings page), body not covered. `KIE_AI_WEBHOOK_HMAC_KEY` (or `OFM_KIEAI_WEBHOOK_HMAC_KEY`) set = only a signed callback no older than `OFM_KIEAI_CALLBACK_TOLERANCE_S` (300) counts. kie.ai's task list (`/api/v1/playground/pageRecordList`, what kie.ai/logs shows) answers an API key `401 Invalid login`: web login only, so it can never be the way back to a lost task.
- `catalog.json` — 152 models (66 image, 86 video), generated by `scripts/sync_kie_catalog.py` (run in the tests container; network only there). The 17 hand-made entries (`CURATED` in the script: schemas tuned to what the old wrappers sent, `fixed`, `default_prompt`) are kept verbatim; every other entry keeps its `label`/`family`/`fixed`/`default_prompt` and gets a fresh `input_schema` per run; entries gone from the docs are kept (jobs name them). Re-running is idempotent.
- Findings (2026-10-22, docs.kie.ai):
  - `https://docs.kie.ai/llms.txt` lists every page; each `<page>.md` embeds the OpenAPI 3.0 YAML of its request. Every generation model -- Market, Veo 3.1, Runway (+Aleph), 4o Image, Flux Kontext, Suno -- is now `POST /api/v1/jobs/createTask` `{model, input}` + `recordInfo`; no separate endpoints any more except Gemini Omni audio/character (`/api/v1/omni/{audio,character}/create`).
  - Docs quirks the script normalises: `oneOf` input variants (Kling 3.0 Omni, PixVerse extend) -> one form (union of fields, required = in every variant) + `anyOf` of the variants for `check`; bogus `allOf: [{type: string}]` on objects (Kling 3.0 Omni) dropped; `pattern` dropped (`^.*\S.*$` rejects multi-line prompts, `^(https?|oss)://` rejects the local paths `check` uses); deprecated fields dropped; an input named `model` (Veo `veo3_fast`, Veo extend `fast`, Flux Kontext `flux-kontext-pro`) collides with /ai/run's own field, so it is pinned in `fixed` to the docs default; `nsfw_checker` pinned false like the curated entries.
  - Not added: 31 Music pages (ElevenLabs, Gemini TTS, Suno -- audio output; runner/`ModelChoice` handle image/video only), 42 Chat pages, Gemini Omni audio/character (own endpoints), Grok Image 2.0 segment-map + OmniHuman human-identification/subject-detection (answer `resultObject` only; `KieRecord.result_urls` reads `resultUrls`), PixVerse reference-to-video (requires `image_references`, an array of objects the form cannot fill), Veo "Get 1080P" (no model id in its spec).
  - Follow-up models take a previous kie task id as a text field (Grok extend/upscale, Runway/Veo extend, Veo get-4k, Seedance 2.5 draft, Grok segment-edit).
  - Prices: `POST https://api.kie.ai/client/v1/model-pricing/page` `{pageNum, pageSize<=100, modelDescription:"", interfaceType:""}` (what kie.ai/pricing calls; 590 rows).
