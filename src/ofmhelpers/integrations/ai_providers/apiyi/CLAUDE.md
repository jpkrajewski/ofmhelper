# integrations/ai_providers/apiyi

## APIYI (`apiyi/`, 2026-11-06)
- One gateway (`https://api.apiyi.com`, `Authorization: Bearer sk-...`) in front of several APIs; each is a family in `apiyi/families/` (`Family`: `prefixes` of the model ids it serves, `submit`, `status`, `download`); `provider.py` only dispatches (a model's family by id, a task's by the tag in its id: `<tag>:<id>`, DashScope's bare). New family = a module + its entry in `families()`. Docs pages saved raw in the session scratchpad; every family read 2026-11-06 by a research pass each.
- **Catalog**: `scripts/sync_apiyi_catalog.py` writes `apiyi/catalog.json` (32 models; hand-made from the docs: APIYI publishes no schema endpoint). Field names keep the app's shape (`image_urls`, `first_frame_url`, `reference_*_urls`, `aspect_ratio`, `resolution`, `duration`); `x-role` = the media type/role a field's files go as.
- **References** (`client.upload`): checked against what APIYI's models take (images JPEG/PNG/BMP/WebP <= 20 MB, video MP4/MOV <= 100 MB, audio WAV/MP3 <= 15 MB; others an MP4/JPEG copy) and answered as a local reference `file://<path>`; each family turns it into what its API takes at submit: a link to this server (`client.link` -> `hosting.link`: DashScope, Seedance), inline base64 (`client.inline`/`data_url`, fitted under the family's limits: Gemini, Seedream, FLUX) or the file itself (multipart: GPT-Image edits, Veo). Image models therefore need no public address (dev works without a tunnel).

- **Keys: one key reaches one token group's models** (`GET /v1/models` per key, dev 2026-11-06): Wan&HappyHorse (14: wan3.0/2.6/2.7, happyhorse), SeeDance2 (4 doubao-seedance), default (259: images, Veo; no Wan). `.env`: `APIYI_API_KEY_WAN` (or `APIYI_API_KEY` / `APIYI_API_KEY_ADMIN`; the admins' form default), `APIYI_API_KEY_SEEDANCE`, `APIYI_API_KEY_DEFAULT`. `apiyi/keys.py` `key_for(model_id, given)`: an admin key is swapped at submit for the key of the model's group (`wan*`/`happyhorse*` -> Wan, `doubao-seedance*`/`seedance*` -> SeeDance2, anything else -> default); a user's own key never; the runner remembers the key the task was made with.
- **A user's keys, one per group (2026-11-11)**: `keys.SLOTS` = the /account entries `apiyi` (default group: images, Veo), `apiyi-wan`, `apiyi-seedance`; `slot_of(model_id)` names the slot a model runs on (`ApiyiProvider.key_slots` / `key_slot`). The submit picks the saved key of the model's slot, an empty slot falls back to the `apiyi` one (`features/account/keys.py`). `key_for` (the .env swap) is unchanged and only ever touches .env keys.
- **A key's group is read from APIYI, not from where it was saved (2026-11-11)**: `client.model_ids()` (`GET /v1/models`, free, one cached answer per key per `OFM_APIYI_KEY_CHECK_TTL_S`, shared with `check_key`) -> `keys.slot_listing` (a list with any model outside Wan and Seedance = the default group; else Wan; else Seedance) -> `ApiyiProvider.slot_of_key(api_key)`. `Keys.for_run` passes over a key whose real group is not the model's and takes the person's next key, for an admin then the .env ones. - An empty account: 403 in the account's language ("Niewystarczające saldo" on ours) -> `ProviderNoCreditsError`. `/v1/dashboard/billing/usage` answers a key but does not count spend (0 after a paid image, 2026-11-06): costs are in APIYI's console log.
- **No idempotency key, no callback, no task list** on any of its APIs: never resent (only a 429), a lost submit answer is lost, never paid twice (self_heal "neither"). `upload` checks the key first (`GET /v1/models`, once per key per `OFM_APIYI_KEY_CHECK_TTL_S`): a wrong key fails before a link is handed out.
- Errors (gateway `{"error": {message, type, code}}` or DashScope `{code, message}`). Submit (`models.raise_for`): 401 auth; 402 or a 403 about quota/balance/saldo = `ProviderNoCreditsError`; "no available channels" naming a group other than Wan&HappyHorse, or a billing mode without pay-as-you-go = `ProviderAuthError` (a key that never works: a /clone-links batch halts), the Wan group's channels down = `ProviderRateLimitError` (nothing created, resent); other 403 auth; 429 rate limit; 5xx unavailable; else input. Task read (`raise_for_read`): only 401 ends the wait, anything else is read again (a paid task is never given up on a read's error). A failed task reads "Flagged content" only on a moderation **code** (DataInspectionFailed, IPInfringementSuspect), never on words in the reason ("green_dress.jpg"). The real failed task (prod 2026-11-07, job 1881dd9b, `tests/fixtures/providers/apiyi/task_moderated.json`) has no `code` field: `error` {message: "[DataInspectionFailed] Green net check rejected image (input)", type: "task_failed"} + the same `fail_reason`, so a leading `[Code]` in the message is the code (`_CODE_IN_MESSAGE`); before that the card read "Failed" (`schemas/errors.py` also matches the bracketed codes, for jobs stored then). Alibaba's check refused a reel Instagram itself restricts ("can't be seen by certain audiences"); the same subject picture passed in 6 other runs. Text fields answered `null` or as numbers are read as text (`models.Text`): an odd body never makes a paid task unreadable. A 200 submit without a task id logs the whole answer at error level; a lost submit answer says it may be made and paid (never resent).
