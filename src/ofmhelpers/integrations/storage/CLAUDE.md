# storage

Cloud storage behind one interface (owner 2026-11-22: "create new folder in integrations called storage, move gdrive there, based on public interface of gdrive create protocol that covers all functions").

- `base.py` `StorageClient`: the Protocol, every public function of the Google Drive client (folder, children, children_of, find_folder, create_folder, ensure_folder, rename, file, find_file, sheet, thumbnail, download, upload, grant, trash_file, storage), and the typed errors callers act on (`DriveError`, `FolderGoneError`, `FolderTrashedError`, `DriveAuthError`, `DriveFullError`, `DriveNotSetUpError`). No delete: `tests/unit/storage/test_never_deletes.py` fails on one.
- `models.py`: the shapes the interface takes and returns (`DriveFolder`, `DriveListing`, `FolderItems`, `DriveThumb`, `DriveDownload`, `DriveSheet`, `SheetTab`, `DriveStorage`); a listed file is `db/drive_folders/schema.py` `DriveFile`.
- `gdrive/`: Google Drive, the one provider so far (client, fake, sheets, its own wire models; details in `gdrive/CLAUDE.md`). A provider is a subpackage whose client satisfies `StorageClient`; mypy checks it wherever the client is returned as one (`gdrive.connect`, `gdrive.connect_as`).
- `wrappers.py`: what works on any provider because it speaks only the protocol: `PerThreadDrive` (one client per thread, opened on first use), `ReadOnlyDrive` (refuses every write: dev reading the live Drive), `ScopedDrive` (writes only inside one root and what it makes or reads there). `constants.py`: their refusal text.
- Callers import the interface, errors, shapes and wrappers from `ofmhelpers.integrations.storage`. A provider's connectors (`ofmhelpers.integrations.storage.gdrive` `connect`, `connect_as`) are imported only by `features/storage/client.py`, the factory (`tests/unit/architecture/test_storage_di.py`); it applies no read-live guard itself: `features/storage/service.py` `StorageService.compose` does.
