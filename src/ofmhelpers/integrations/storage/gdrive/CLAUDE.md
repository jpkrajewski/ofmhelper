# gdrive

Google Drive as a **service account** (`settings.gdrive`), for /drive (features/storage/folders.py).

- Typed errors callers act on: `FolderGoneError` (404 / trashed / not shared), `DriveFullError` (403 `storageQuotaExceeded`), `DriveAuthError` (Google refused the person's sign-in; message = `RECONNECT` "Reconnect Google Drive on your Account page", safe for a page; Google's text only on `__cause__` and in the log). Any other failure is a `DriveError` with a readable message.
- `client.py` `_failure`: non-retryable `RefreshError` (invalid_grant: revoked / expired / 6 months unused), HTTP 401, or 403 `insufficientPermissions`/`ACCESS_TOKEN_SCOPE_INSUFFICIENT` (Drive unticked on Google's granular consent) -> `DriveAuthError`; a *retryable* `RefreshError` (token endpoint 5xx) stays a plain `DriveError` (reconnecting would not help). Before, all of it was the `('invalid_grant: ...', {...})` tuple repr on every /clone-links card.
- `ScopedDrive` (`integrations/storage/wrappers.py`, live-read mode) writes only inside dev's root and folders in it it made, found (`find_folder` in a writable parent) or read (`folder()` whose parent is writable) -- so a remembered review folder id is writable after one `folder()` (features/storage/review.py `StorageServiceReview.folder`).
- `connect()` gives one `Drive` per thread: httplib2 is not thread-safe. `integrations/storage/wrappers.py` `PerThreadDrive(open_drive)` is a `StorageClient` that calls `open_drive` (a `connect` / `connect_as` partial) on its first use in each thread and keeps that one for the thread: what `features/storage/client.py` hands out, so one injected client can be shared by a thread pool. `connect` / `connect_as` return the raw client: the read-live guard is `StorageService.compose`'s. `find_folder` returns the oldest of that name, so a hand-made one is reused. `upload` only on a person's Drive (`connect_as(refresh_token)`). `service_account_email()` = who the root must be shared with.
- `FakeDrive` (`OFM_FAKE_EXTERNALS`) has real semantics (non-unique names, trash != delete, visibility = shared item or a folder above it, owner per item) and is kept honest by `tests/contract/test_drive_contract.py`.
- Never deletes or moves anything for good: `trash_file` puts a file in Drive's trash (30 days). `ScopedDrive.trash_file` only for a file in a folder it may write in (/trials replaces what is in its dev TRIALS twin).
- `sheet(file_id)` -> `DriveSheet` (for /download-assets "Download from Drive sheet", `features/downloads/sheet.py`): a Google Sheet's cells, every tab; `sheets.py` `read_xlsx` reads Drive's xlsx export (date cell -> `date`, other filled cell -> its text, a label over a hyperlink -> the link, trailing empty rows cut).

## Setup
1. Google Cloud Console: enable **Google Drive API**; IAM -> Service accounts -> create, Keys -> JSON.
2. Share the Drive folder with the account's `client_email` as **Editor**.
3. `.env`: `OFM_GDRIVE_SERVICE_ACCOUNT='<key JSON, one line>'` (single quotes: compose and dotenv keep it literal), `OFM_GDRIVE_ROOT_FOLDER=<sandbox folder id>`: only the live Drive contract tests use these. The app uses each owner's own Drive (Google sign-in) and finds their root by name, `StorageServiceFolders.root_name()` ("DEV - ALL ACCOUNTS" unless `OFM_ENV=production`, set on the server only).
4. Live Drive contract tests: a separate sandbox folder shared with the bot as `OFM_GDRIVE_ROOT_FOLDER`. Outside production the app never uses a stored root not named "DEV - ALL ACCOUNTS" (features/storage/folders.py `StorageServiceFolders.usable_root`), so a dev copy of the prod DB cannot write into the live folders.

## Findings
- Reading a Google Sheet needs no Sheets API and no new scope: `files.export(fileId, mimeType=<xlsx>)` with the Drive scope (checked live 2026-11-12 on prod's `content_links`: 6.9 KB, ~0.5 s). Export as `text/csv` gives the FIRST tab only and a date as its displayed text (`12/11/2026`: day-month or month-day by the sheet's locale); as xlsx every tab comes and a date cell is a real `datetime` with its `number_format` beside it, so nothing is parsed from text. Exports are capped at 10 MB. A file that is not a Docs-editor file refuses the export (403). The used range runs past the filled cells (46 rows for 4 filled: formatting). https://developers.google.com/workspace/drive/api/guides/manage-downloads#export-content
- Service account over OAuth: no consent screen, no 7-day refresh-token expiry of an unpublished OAuth app, and the full `drive` scope (needed: `drive.file` sees only files the app created, never the VA's uploads or an existing folder) is a *restricted* scope that a public OAuth app must pass Google's security assessment for. Sharing one folder with the account limits it to that folder. https://developers.google.com/workspace/drive/api/guides/api-specific-auth
- Service accounts have no storage quota: they can make folders (no bytes) in a user's folder but uploads into My Drive fail ("Service Accounts do not have storage quota"). Folders the bot makes are owned by it; files the VA uploads stay the VA's. A Shared Drive removes both caveats. https://developers.google.com/workspace/drive/api/guides/about-shareddrives
- `thumbnailLink` is short-lived and, for a non-public file, answers only with the caller's token: hence the server-side proxy, not an `<img>` straight to Google. Its `=s220` suffix sets the size. Videos get one once Drive has processed them. https://developers.google.com/workspace/drive/api/reference/rest/v3/files
- A 404 on `files.get` means "not shared with this account" as often as "does not exist": Drive does not tell them apart.
- `files.update` of an id that does not exist answers **500 "Internal Error"** 2-4 times in 15 (any id shape, even real-looking 33-char ones; the same id kept 500ing through every retry), `files.get` 404s (probed 2026-10-24, retries off). Hence `trash_file` gets first: an already-gone file is `FolderGoneError`, not a ~40 s retried `DriveError`.
- `files.list` of a TRASHED folder still returns its children (checked live 2026-10-21): only `folder()` (files.get `trashed`) tells a deleted folder, so /drive checks the folder before listing it. A missing/unshared parent is usually a 404, but ~1 in 5 unknown ids list as empty instead, the same every time (probed 2026-10-24, 17 of 120): gone is only ever told by `folder()`. Made-up test ids: `"1"` + 32 base64url, Drive's shape (some made-up hex ids 400 on every get).
- `'a' in parents or 'b' in parents` lists several folders in one call, but ONE unknown/unshared id 404s the whole query (checked live 2026-10-22): `children_of` gets only ids the root listing just returned.
- A service account cannot upload into a My Drive folder (403 `storageQuotaExceeded`, checked live 2026-10-22): uploads need a user's OAuth token or a Shared Drive.
- `drive_credentials` builds `Credentials(token=None, refresh_token=...)`: the first request refreshes, so a dead grant surfaces at the first Drive call as google-auth `RefreshError(error_details, response_data, retryable=...)` (google/oauth2/_client.py `_handle_error_response`; `_can_retry` = 5xx / `server_error` / `temporarily_unavailable` only, invalid_grant is final, fails in < 1 s). googleapiclient's own retries never see it. A published OAuth app ("In production") has no 7-day expiry (signin/CLAUDE.md); left triggers: revoked under Third-party apps, 6 months unused, Google's per-client token cap. https://developers.google.com/identity/protocols/oauth2#expiration
- Drive's error body: `HttpError.error_details` is the first of `detail`/`details`/`errors` present (googleapiclient/errors.py `_get_reason`); Drive v3 sends `errors: [{reason: "storageQuotaExceeded"|"insufficientPermissions"|...}]`, newer ones also `details: [{reason: "ACCESS_TOKEN_SCOPE_INSUFFICIENT"}]`. `_reasons` reads either. https://developers.google.com/workspace/drive/api/guides/handle-errors
- Parallel /clone-links reviews of one person (10 RQ workers) each did find-then-create on the root and GOOD/TRIAL REELS: duplicates of one name. features/storage/review.py `StorageServiceReview.folder` holds `lock:drive-review:<user_id>` (Redis, `OFM_GDRIVE_REVIEW_LOCK_S`, fail-open) around root + folder resolution (upload outside), re-finds after a create (oldest kept) and remembers the folder id in Redis (`drive:review-folder:<user>:<root>:<name>`, checked with one `folder()`: gone / renamed / moved -> resolved again).
- Trashing a folder trashes its contents too, asynchronously on Google's side: `children()` (`trashed = false`) of a just-trashed folder lists its children only until that cascade lands, then nothing (live contract 2026-11-20: 2 of 20 runs listed nothing even after 10 s). Never read a trashed folder's contents; `folder()` raising `FolderGoneError` is the stable signal (the folder's own `trashed` flag is set at once). Not every caller asks it first: `features/trials/tasks.py` `_list_posted` lists a stored POSTED id directly (IMPROVEMENTS.md). `FakeDrive.trash` does not cascade.
