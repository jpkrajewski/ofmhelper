# gdrive

Google Drive as a **service account** (`settings.gdrive`), for /drive (web/drive_folders.py). Google's own libraries (`google-api-python-client`, `google-auth`).

- `base.py` — `DriveApi` (Protocol every Drive implements; callers type against it), `DriveError` and its typed kinds callers act on: `FolderGoneError` (404 / trashed / not shared), `DriveFullError` (403 `storageQuotaExceeded`), `DriveAuthError` (Google refused the person's sign-in; message = `RECONNECT` "Reconnect Google Drive on your Account page", safe for a page; Google's text only on `__cause__` and in the log).
- `client.py` `_failure` (2026-10-25, review #13/#16): non-retryable `RefreshError` (invalid_grant: revoked / expired / 6 months unused), HTTP 401, or 403 `insufficientPermissions`/`ACCESS_TOKEN_SCOPE_INSUFFICIENT` (Drive unticked on Google's granular consent) -> `DriveAuthError`; a *retryable* `RefreshError` (token endpoint 5xx) stays a plain `DriveError` (reconnecting would not help). Before, all of it was `DriveError(f"{what}: {exc}")` = the `('invalid_grant: ...', {...})` tuple repr on every /clone-links card.
- `ReadOnlyDrive` / `ScopedDrive` (live-read mode): `ScopedDrive` writes only inside dev's root and folders in it it made, found (`find_folder` in a writable parent) or read (`folder()` whose parent is writable) -- so a remembered review folder id is writable after one `folder()` (web/drive_folders.py `review_folder`).
- `client.py` — `connect()` -> `Drive` (one per thread: httplib2 is not thread-safe); `FakeDrive` under `OFM_FAKE_EXTERNALS`. `folder` (with `parents`; raises `FolderGoneError` for missing / trashed / not shared), `children` (paged, newest first, no trash), `children_of(ids)` (several folders in one OR query, 40 ids per query; /drive's batch), `find_folder` (oldest of that name, so a hand-made one is reused), `create_folder`, `ensure_folder`, `rename`, `file(id)` (with `parents`, `thumbnailLink`, `ownedByMe`; trashed = `FolderGoneError`), `thumbnail(file, px)` (fetches its `thumbnailLink` with the account's token), `upload(parent, path, name, mime)` (resumable, 8 MiB chunks; only a person's Drive: `connect_as(refresh_token)`), `grant(item, email)` (Editor, no notification email). Every request `execute(num_retries=OFM_GDRIVE_RETRIES)`. Any failure is a `DriveError` with a readable message. `service_account_email()` = who the root must be shared with.
- `models.py` — `DriveFolder`, `DriveFile` (Drive's field names as aliases; `kind` image/video/folder/file, `url`).
- `fake.py` — `FakeDrive`: same interface, real semantics (non-unique names, parents, trash != delete, visibility = shared item or a folder above it, owner per item, previews only where there are). Memory, or `OFM_FAKES_DIR/drive.json` under `fcntl` lock (the app under e2e and the test share it). Test hooks: `seed_folder`, `add_file`, `move` (a person dragging a file; the app never moves), `trash`, `delete`, `rename_by_hand`, `share`/`unshare`, `fail_on`, `set_storage` (an upload past the limit = `DriveFullError`), `refuse_sign_in(email)` (every `FakePersonDrive` call as them = `DriveAuthError`), `named`, `calls`/`writes`. Kept honest by `tests/contract/test_drive_contract.py`.
- Never deletes or moves anything.

## Setup
1. Google Cloud Console: enable **Google Drive API**; IAM -> Service accounts -> create, Keys -> JSON.
2. Share the Drive folder with the account's `client_email` as **Editor**.
3. `.env`: `OFM_GDRIVE_SERVICE_ACCOUNT='<key JSON, one line>'` (single quotes: compose and dotenv keep it literal), `OFM_GDRIVE_ROOT_FOLDER=<sandbox folder id>`: only the live Drive contract tests use these. The app uses each owner's own Drive (Google sign-in) and finds their root by name, `web/drive_folders.root_name()` ("DEV - ALL ACCOUNTS" unless `OFM_ENV=production`, set on the server only).
4. Live Drive contract tests: a separate sandbox folder shared with the bot as `OFM_GDRIVE_ROOT_FOLDER`. Outside production the app never uses a stored root not named "DEV - ALL ACCOUNTS" (`drive_folders.usable_root`), so a dev copy of the prod DB cannot write into the live folders.

## Findings
- Service account over OAuth: no consent screen, no 7-day refresh-token expiry of an unpublished OAuth app, and the full `drive` scope (needed: `drive.file` sees only files the app created, never the VA's uploads or an existing folder) is a *restricted* scope that a public OAuth app must pass Google's security assessment for. Sharing one folder with the account limits it to that folder. https://developers.google.com/workspace/drive/api/guides/api-specific-auth
- Service accounts have no storage quota: they can make folders (no bytes) in a user's folder but uploads into My Drive fail ("Service Accounts do not have storage quota"). Folders the bot makes are owned by it; files the VA uploads stay the VA's. A Shared Drive removes both caveats. https://developers.google.com/workspace/drive/api/guides/about-shareddrives
- `thumbnailLink` is short-lived and, for a non-public file, answers only with the caller's token: hence the server-side proxy, not an `<img>` straight to Google. Its `=s220` suffix sets the size. Videos get one once Drive has processed them. https://developers.google.com/workspace/drive/api/reference/rest/v3/files
- A 404 on `files.get` means "not shared with this account" as often as "does not exist": Drive does not tell them apart.
- `files.update` of an id that does not exist answers **500 "Internal Error"** 2-4 times in 15 (any id shape, even real-looking 33-char ones; the same id kept 500ing through every retry), `files.get` 404s (probed 2026-10-24, retries off). Hence `trash_file` gets first: an already-gone file is `FolderGoneError`, not a ~40 s retried `DriveError`.
- `files.list` of a TRASHED folder still returns its children (checked live 2026-10-21): only `folder()` (files.get `trashed`) tells a deleted folder, so /drive checks the folder before listing it. A missing/unshared parent is usually a 404, but ~1 in 5 unknown ids list as empty instead, the same every time (probed 2026-10-24, 17 of 120): gone is only ever told by `folder()`. Made-up test ids: `"1"` + 32 base64url, Drive's shape (some made-up hex ids 400 on every get).
- `'a' in parents or 'b' in parents` lists several folders in one call, but ONE unknown/unshared id 404s the whole query (checked live 2026-10-22): `children_of` gets only ids the root listing just returned.
- Each Drive round trip is ~0.3-0.6 s (dev, 2026-10-22): /drive cost 3 per account (2-8 s on prod with ~10 accounts); batched it is 3 sequential calls (~1.5 s) whatever the account count. A service account cannot upload into a My Drive folder (403 `storageQuotaExceeded`, checked live 2026-10-22): uploads need a user's OAuth token or a Shared Drive.
- `build(..., static_discovery)` defaults to the discovery document bundled with the library: no network call to build a service.
- `drive_credentials` builds `Credentials(token=None, refresh_token=...)`: the first request refreshes, so a dead grant surfaces at the first Drive call as google-auth `RefreshError(error_details, response_data, retryable=...)` (google/oauth2/_client.py `_handle_error_response`; `_can_retry` = 5xx / `server_error` / `temporarily_unavailable` only, invalid_grant is final, fails in < 1 s). googleapiclient's own retries never see it. A published OAuth app ("In production") has no 7-day expiry (signin/CLAUDE.md); left triggers: revoked under Third-party apps, 6 months unused, Google's per-client token cap. https://developers.google.com/identity/protocols/oauth2#expiration
- Drive's error body: `HttpError.error_details` is the first of `detail`/`details`/`errors` present (googleapiclient/errors.py `_get_reason`); Drive v3 sends `errors: [{reason: "storageQuotaExceeded"|"insufficientPermissions"|...}]`, newer ones also `details: [{reason: "ACCESS_TOKEN_SCOPE_INSUFFICIENT"}]`. `_reasons` reads either. https://developers.google.com/workspace/drive/api/guides/handle-errors
- Parallel /clone-links reviews of one person (10 RQ workers) each did find-then-create on the root and GOOD/TRIAL REELS: duplicates of one name. web/drive_folders.py `review_folder` holds `lock:drive-review:<user_id>` (Redis, `OFM_GDRIVE_REVIEW_LOCK_S`, fail-open) around root + folder resolution (upload outside), re-finds after a create (oldest kept) and remembers the folder id in Redis (`drive:review-folder:<user>:<root>:<name>`, checked with one `folder()`: gone / renamed / moved -> resolved again).
