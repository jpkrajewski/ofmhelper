# llm

Language models that read text, images and video and answer in a typed shape, behind one interface. The app never names a provider or model.

```python
from ofmhelpers.llm import LLMUse, Prompt, get_llm

found = get_llm(LLMUse.VIDEO).ask(
    Prompt.of("Subject:", photo, "Reel:", video, system=RULES), Verdict
)
```

## Shared layer
- `models.py` — `Prompt` (`parts` in order: `TextPart` / `MediaPart`, `system`, `temperature` None = the provider's default), `Prompt.of(*str|Path)`, `MediaPart.of(path)` (kind from the file name; not image/video/audio = `LLMInputError`), `MediaKind`, `LLMUse` (VIDEO, CHAT). What one attempt returns: `Reply(text, usage)`, `Usage(input_tokens, thinking_tokens, output_tokens)` (None = not reported; `Usage.summed`).
- `base.py` — `LLMProvider`: class vars `name`, `label`, `media` (kinds it reads), `max_images`, `temperature` (sent when the prompt names none; None = not sent); `default_key()`/`default_model()` (settings); `_ask(prompt, Answer, timeout_s) -> Reply` = one attempt, over within `timeout_s`. `ask(prompt, Answer)` / `answered(prompt, Answer, deadline=)` do the rest once for every provider: a video for an images-only provider becomes a note + contact sheet (`frames.py`), media it cannot read / too many images refused before sending, `LLMUnavailableError` retried (`OFM_LLM_RETRIES` 4; the provider's retry hint, else 5 s doubling, max 60 s; a hint over the max -- a daily quota gone -- fails at once), a wrong-shape answer asked again (`OFM_LLM_SHAPE_RETRIES` 1), the answer validated (`LLMOutputError`). `deadline` (a `time.monotonic()` value; `clone_ai_check` gives a whole check one): each request's timeout is `OFM_LLM_TIMEOUT_S` cut to the time left, and a retry or wait that would end past it (less than 1 s left for a request) raises `LLMUnavailableError("<label> took too long")`, the failure it cut short in `.detail`; no re-ask either. `Answered`: answer, raw text, provider label, model, attempts, seconds, `input/thinking/output_tokens` summed over every attempt that got an answer. Registry like aigenproviders: `@register_llm`, `llm_names`, `llm_class`. `get_llm(use, provider=, api_key=, model=)`: the default for `use` (`LLM_DEFAULT_VIDEO` = gemini, `LLM_DEFAULT_CHAT` = groq), each `<provider>[:<model>]`; no key = `LLMConfigError`. Video work also has a fallback chain, `settings.llm.video_chain` = `LLM_DEFAULT_VIDEO` (`gemini:gemini-3.6-flash`) then `LLM_FALLBACK_VIDEO` (default `gemini:gemini-3.8-flash,gemini:gemini-3.5-flash,gemini:gemini-3.5-flash-lite`: Gemini only, Groq judged every reel GOOD -- Findings), walked by `clone_ai_check._ask`: unavailable / not set up hands over to the next, anything else is the answer; providers that cannot read video are skipped there (clone_ai_check).
- `errors.py` — `LLMError(message, detail)` family: `LLMConfigError` (no key, unknown provider/model), `LLMAuthError` ("<label>: wrong API key"), `LLMInputError`, `LLMRefusedError` (safety filter), `LLMOutputError`, `LLMUnavailableError` (retryable, `retry_after_s`). Provider wording in `.detail` + exception note, never in the message.
- `frames.py` — `contact_sheet(video, dest, frames, frame_px, timeout)`: `frames` stills from the first frame to the last of the video stream (`video_seconds`: ffprobe `v:0` duration, the file's when the stream has none -- audio running past the picture would plan stills with no frame; `still_times`: the last 0.1 s before the end, a seek to the very end decodes nothing), one ffmpeg seek each, tiled in time order with PIL, each labelled with its time ("0:07.5") so a model can say where. HDR (`color_transfer` arib-std-b67 HLG / smpte2084 PQ) goes through `zscale` to BT.709 SDR first, SDR white at 203 nits (BT.2408; the exact inverse of the iPhone export, brighter highlights clip): read as SDR, the HLG export's stills were ~40% less saturated (measured 2026-10-25). Motion between stills is lost. Used for images-only providers (`OFM_LLM_VIDEO_SHEET_FRAMES` 9) and by `clone_ai_check`.
- `fakes.py` — what every fake shares: `example(schema)` (the plainest value a JSON Schema allows: true, 0, "", [], first enum value -- a checker's fake answer reads "passed"), `field(camel, snake)`.
- `chat_completions.py` — `ChatCompletionsLLM`: OpenAI-style `POST <base_url>/chat/completions` over httpx (no vendor SDK: one wire for every vendor; each SDK, or OpenAI's v3 with its httpx2 fork and daily releases, would be a dependency for one endpoint). Images inline as base64 data URLs, shrunk to `OFM_LLM_IMAGE_MAX_SIDE` 1024 / 3 MB (free plans count tokens per minute). `response_format` strict JSON Schema via `strict_schema` (refs inlined, objects closed, all properties required, Cerebras' rejected keywords dropped), and the same schema written into the system message: Groq checks the answer after generating it, and a model never shown the field names invents its own (400 `json_validate_failed`). `temperature` 0 unless the prompt names one; tokens from `usage` (`prompt_tokens`, `completion_tokens`, reasoning inside the latter). Errors: 401/403 auth, 404 config, 429 unavailable (`retry-after`), 408/409/5xx unavailable, else input; `finish_reason: content_filter` = refused. A vendor = subclass (`base_url`, `max_images`, key/model/fake hooks).
- `chat_completions_fake.py` — `FakeChatCompletions(host, key, models, max_images)`: 401 other key, 404 unknown model, 400 over the image cap or a non-strict schema; queued `answer_next`/`fail_next`/`filter_next`, else `example`; every answer reports `USAGE`; `requests`, `timeouts` (each request's read timeout).

## Providers
- `gemini/` — Google AI Studio, `google-genai` SDK (2.29.0). The only free tier that watches real video. `gemini-3.8-flash` (`OFM_GEMINI_MODEL`), `GEMINI_API_KEY`. Media <= `OFM_LLM_INLINE_MAX_BYTES` (14 MB) inline, else Files API upload -> poll until ACTIVE (`OFM_LLM_FILE_READY_TIMEOUT_S`) -> deleted after the answer, all within the attempt's `timeout_s` (`HttpOptions.timeout`, the generate request getting what an upload left). `response_json_schema`; no temperature sent (Findings). Tokens from `usage_metadata` (`prompt_token_count`, `thoughts_token_count`, `candidates_token_count`). SDK retries off (base retries). Errors: 400 "API key not valid"/401/403 auth, 404 config, 429 unavailable with `RetryInfo.retryDelay`, 408/499/5xx unavailable, else input; `promptFeedback.blockReason` / safety finish reasons = refused. Fake (`fake.py`): wire under the SDK's `HttpOptions.httpx_client` -- generateContent, resumable upload, files get/delete; FAKE_KEY only; `MODELS` else 404; a fileData part naming a file not ACTIVE = 400; hooks `answer_next`, `fail_next(code, status, msg, retry_delay_s)`, `refuse_next`, `fail_processing`, `polls_until_active`; every answer reports `USAGE`; `requests`, `models`, `timeouts` per generateContent. `MODELS` holds every model of the default `video_chain` (unit test).
- `groq/` — `ChatCompletionsLLM` at `https://api.groq.com/openai/v1`, `qwen/qwen3.8-27b` (`OFM_GROQ_MODEL`), `GROQ_API_KEY`, images only, max 3.
- `cerebras/` — `ChatCompletionsLLM` at `https://api.cerebras.ai/v1`, `qwen-3.8-27b` (`OFM_CEREBRAS_MODEL`), `CEREBRAS_API_KEY`, images only, max 2.

## Adding a provider
OpenAI-style API: `<name>/provider.py` subclassing `ChatCompletionsLLM` + `<name>/fake.py` (a `FakeChatCompletions`). Other wire: subclass `LLMProvider`, write `_ask` mapping failures onto `errors.py`, a wire fake. Either way: key/model fields in `LLMSettings`, the fake in both conftests' cache lists, an entry in `tests/contract/test_llm_contract.py` PROVIDERS. Nothing else changes.

## Findings (2026-10-24/25)
- Measured 2026-10-25 (tests image, ffmpeg 7.1.5 Debian, zscale/tonemap built in): the fakes' colour bars as the iPhone export's HLG BT.2020 10-bit, stills read as SDR: HSV saturation 201 -> 122; through `zscale ... t=bt709 ... npl=203`: 195. PQ the same way: 91 -> 195 (a `tonemap=hable` path at npl 100 got the colour but dimmed luma 126 -> 98). The `colorspace` filter cannot read HLG/PQ transfers, so zscale is the only route.
- Gemini free tier (ai.google.dev/gemini-api/docs/pricing): `gemini-3.8-flash`, `3.7-flash`, `3.6-flash`, `3.5-flash`, `3.5-flash-lite`, `3.1-flash-lite` free (3.7/3.5-flash proven by their free-tier 429 quota below). 2.0 models shut down, 2.5 only for past users. Rate limits per project, shown in AI Studio only. Video: 1 fps sampled, ~300 tokens/s (100 at low resolution); inline under 20 MB a request.
- Gemini unpaid-tier terms -- DECIDED 2026-10-25: the user accepted the unpaid tier for /clone-links checks (contact sheets of generated reels of real customers' likeness). Terms: https://ai.google.dev/gemini-api/terms (last updated 2026-04-28, effective 2026-03-23), Unpaid Services: inputs/outputs used "to help with quality and improve our products", "human reviewers may read, annotate, and process your API input and output", "Do not submit sensitive, confidential, or personal information to the Unpaid Services." EEA / Switzerland / UK: the Paid Services data terms apply to all Services there, unpaid quota included, and "You may use only Paid Services when making API Clients available to users in the European Economic Area, Switzerland, or the United Kingdom." Paid tier (a billed project's key): no training, no human review; it also lifts the 20 a day below. Nothing in code picks the tier: the key's project does.
- Gemini 3.x sampling (ai.google.dev/gemini-api/docs/whats-new-gemini-3.6 and -3.8, last updated 2026-10-13): "`temperature`, `top_p`, and `top_k` are deprecated and ignored" from 3.6 Flash / 3.5 Flash-Lite on, "In future model generations, supplying these parameters returns an HTTP 400 error", "Remove these parameters from all requests"; the older Gemini 3 guide advised keeping the default 1.0 (lower may loop). Hence `GeminiLLM.temperature` None: none sent unless a prompt names one. 3.8 Flash: `thinking_level` low/medium (default)/high, `minimal` an error -- not set (theory: it is what makes 3.8 take 60-87 s).
- Gemini usage (`usage_metadata`): `prompt_token_count`, `thoughts_token_count` (thinking, billed as output), `candidates_token_count` (the answer). Kept per answer (`Answered.*_tokens`); no prices until a billed key exists.
- google-genai 2.29.0 writes `inlineData.mime_type` / `fileData.file_uri` snake case inside camelCase parts (Google's parser takes both); the request config is camelCase (`responseJsonSchema`, `systemInstruction`). Upload: `POST /upload/v1beta/files` -> `x-goog-upload-url` header -> chunks with `X-Goog-Upload-Command: upload[, finalize]`, answered `x-goog-upload-status: active|final`, body `{"file": ...}`.
- Groq (console.groq.com/docs): vision = `qwen/qwen3.8-27b` (max 3 images, 20 MB a URL request) and `meta-models/muse-spark-open` (limited preview, 5). Free: 30 RPM, 1K RPD, 8K TPM, 200K TPD, per organization. Strict JSON Schema on qwen3.8-27b, muse-spark-open, gpt-oss-20b/120b; no streaming with it. Qwen 3.8 returns no reasoning at default effort; JSON mode needs `reasoning_format` parsed/hidden if set (raw = 400). Data: not retained by default, logs up to 30 days, Zero Data Retention switch.
- Cerebras (inference-docs.cerebras.ai): `qwen-3.8-27b` (images: 2 a request, 10 MiB payload) and `gpt-oss-120b`; Free Trial 5 RPM, 30K uncached TPM, 1M TPD. Strict schema: no `oneOf/allOf/not/pattern/format/minItems/maxItems/patternProperties`, local non-recursive `$ref` only, depth 10.
- Measured on dev 2026-10-25 (two real 6-8 s reels, one 9:16 contact sheet of 7-9 stills each, free tier): `gemini-3.8-flash` answered in 60 s and 87 s, one attempt each, verdict + reasoning sensible; the sheet took ~4 s. Hence `OFM_LLM_TIMEOUT_S` 300 (was 120).
- Quotas probed 2026-10-25 (429 `quotaId`): Gemini free tier `GenerateRequestsPerDayPerProjectPerModel-FreeTier` = **20** for each of 3.8/3.7/3.6/3.5-flash (reset midnight Pacific); `*-pro*`, omni, nano-banana = 0 (paid only); lite and `gemini-3-flash-preview` still open after the flash ones ran out -- **`3.5-flash-lite`'s daily cap is unmeasured** (open after 7 checks; it decides whether the chain holds ~60 or many more checks a day). A per-day 429's `retryDelay` is the time to the reset (~10,000 s, over `OFM_LLM_RETRY_MAX_WAIT_S`), so an exhausted model fails at once (~1 s, no wait) and the chain moves on. Groq: 1,000 requests/day, 8K tokens/min, **200K tokens/day** per organization (`x-ratelimit-*` headers show requests and TPM only; the TPD 429 names "tokens per day"). An AI check is ~1.1-2.8K Groq tokens. Dev and prod use the same Gemini project and Groq organization: dev testing spends prod's quota. The live contract tests (`tests/contract/test_llm_contract.py`) therefore ask Gemini on `3.5-flash-lite` with no retries, 2 real calls a run, and skip (with Google's reason) when out of quota or down; a provider with no key in .env is skipped.
- AI check quality, measured 2026-10-25 on 7 dev reels (one a man in a strapless tube top, six clean, each checked frame by frame at 4K): `gemini-3.5-flash-lite` 7/7 (sheet, 2-6 s, "strapless tube top on man: blocking"); `gemini-3-flash-preview` 1/7 (GLITCHY on all, sheet and video alike: "fused fingers", "face morphing" not there at full resolution); Groq `qwen3.8-27b` 6/7 by saying GOOD to all, reasoning boilerplate, at 1024 px, 3 images or a still-by-still prompt alike, and 13 of 34 answers invented keys (asked again, the short "no glitches" answer was the one that got through). Hence the video chain is Gemini only (`LLM_FALLBACK_VIDEO`).
