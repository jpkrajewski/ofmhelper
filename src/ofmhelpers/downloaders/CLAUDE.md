# downloaders

Media from external URLs.

- `generic.py` — videos via yt-dlp (`DownloadConfig`, `download`, `download_all`; TikTok H.264 re-encode, YouTube PO-token workarounds). The only place that downloads video.
  - `site_of(url)`: the yt-dlp extractor made for the URL's site (`IE_NAME`), None when only Generic would try; pattern match only, no request (~0.3 s first call, ~3 ms after, 2026-10-25). /clone-links Check uses it to fail junk links before any download.
  - `_PROXIED_SITES` (Instagram: `OFM_IG_PROXIES`, 1 + `OFM_IG_PROXY_RETRIES` tries): metadata logged out via a proxy, file direct from the CDN, then the cookies + direct try last. Verified on prod 2026-10-21: server IP logged out -> "redirected to the login page"; cookies.txt -> `HTTP Error 400`; proxy logged out -> OK.
  - `DownloadConfig.single_post(**fields)` (2026-10-25, review #12/#37): the linked post only -- `noplaylist` (`watch?v=X&list=PL` = X, an Instagram story link = that story, not the tray), `playlist_items="1:N"` (`OFM_DOWNLOAD_SINGLE_POST_ITEMS`, 10: a carousel's slides; yt-dlp pulls lazy entries only up to it, checked), `allowed_extractors=["default", "-generic"]` (`SITE_EXTRACTORS_ONLY`; checked in yt-dlp 2026.10.21: Generic not loaded, `facebook.com/flx/warn/?u=<host>` fails "No suitable extractor" before any request). Plain `DownloadConfig()` (/download-media) keeps playlists and Generic.
  - `video_info(url, cookiefile, *, socket_timeout=None)`: /clone-links' preview read (no download), with `single_post` (+ yt-dlp `socket_timeout`; the preview passes `settings.clone_links.preview_socket_timeout_s`). Tries like `download`; on failure `error` = the LAST try's text (the login direct, when the site has proxies) and `logged_out_error` = the first proxy's when there were several tries (raw yt-dlp text: logs/classification only, never on a page). A whole-second `duration` (TikTok floors to int) is passed on as is: not probed (TikTok's stream wants yt-dlp's per-format `http_headers` + cookies, so a bare ffprobe would be another fragile request per link; `web/clone_links/preview.py` treats whole seconds >= the limit as too long instead).
  - `reencode_to_h264`: ffmpeg bounded by `OFM_DOWNLOAD_REENCODE_TIMEOUT_S` (900); timeout/failure = original kept, partial `_h264.mp4` removed.
- `images.py` — images via the `gallery-dl` CLI; filenames use `post_shortcode`. `_LOGIN_WALLS` turns a login-redirect error into "upload your fresh cookies.txt at /cookies". `ImageDownloadConfig.max_items` = `--range 1-N`.
  - Instagram photo/carousel posts need a working login. Verified 2026-10-22 on `/p/DGUaB0Rtazx`: gallery-dl 1.32.17 logged out (direct, via `OFM_IG_PROXIES`, `api=graphql`) -> "HTTP redirect to login page"; the logged-out post page carries only the cover image (1 `image_versions2`, no `video_versions`); yt-dlp -> "There is no video in this post" (prod via proxy: "No video formats found!"). Not a yt-dlp bug: it downloads video only.
- `media.py` — any link (/download-media): yt-dlp then gallery-dl, or gallery-dl first for photo-post links (`sites.IMAGES_FIRST`: Instagram `/p/`, X/Twitter, Pinterest, TikTok `/photo/`); first that gets files wins, both errors kept otherwise. Each URL gets its own `downloads/<hex>/`. `download(url, cookiefile)` keeps the files (job results). `downloaded(url, cookiefile, *, single=False)` = context manager for callers that copy what they keep (/clone-links' worker: asset store): yields the `DownloadResult`, removes the URL's folder (partial files too) on exit, also when the block raises; `single=True` = `DownloadConfig.single_post` for yt-dlp + `max_items` for gallery-dl.
- `savers.py` — the fallback for Instagram posts (`sites.saver_supported`: `/p/`, `/reel(s)/`, `/tv/`) every other tool refused (login-walled, age-gated: "This content isn't available to everyone", prod Logfire 2026-10-25..29). Reel-saver sites saveinta.com then snapreels.net, tried in order, first with files wins: GET `{base}/en` scrapes the short-lived `k_exp`/`k_token` pair, POST `{base}/api/ajaxSearch` (`q`=post, `t=media`, `v=v2`, empty `cftoken` — no CAPTCHA needed today), the JSON `data` carries `dl.snapcdn.app` links (saveinta's packed into an eval'd script — `_unpack`; snapreels' plain HTML; both sites one operator). Files stream named `{shortcode}_{n}.{ext}`, ext from the content type; `single=True` caps at `single_post_items`. A new saver = one entry in `_SAVERS`. `savers_fake.py` — the wire fake (saveinta.com/snapreels.net/dl.snapcdn.app) for OFM_FAKE_EXTERNALS.
- `sites.py` — `IMAGES_FIRST` / `images_first(url)`: which links are photo posts (import-free; shared by `media.py` and `fake.py`). `SAVER_POST` / `saver_supported(url)`: which links the saver fallback takes (Instagram posts only; shared by `savers.py` and `savers_fake.py`).
- `models.py` — `DownloadResult`, `VideoInfo` (`error`, `logged_out_error`), `YtDlpOptions` (`playlist_items`, `allowed_extractors`, `socket_timeout`: None = yt-dlp's default, left out of `to_ydl()`), `YtDlpInfo`.
- `fake.py` — OFM_FAKE_EXTERNALS: a URL "downloads" to a generated mp4 (video) or two jpgs (post); "fake-fail" in the URL fails. `info()` (the fake `video_info`) agrees with the fake download: a photo-post link -> "No video at this link (a photo post?)"; markers "fake-long" -> 20 s, "fake-login" -> an error with "login required", "fake-thumb" -> a cover on the fake Instagram CDN (`instagram/fake.py` `CDN`, served via `utils/outbound.py`). The download of "fake-long" is still the 2 s clip (worker tests patch the length).
- `cookies.py` — cookies.txt as text, never a shared file (2026-10-22): each user's own lives encrypted in Postgres (`web/stores/cookies.py`) and the caller passes it in. `cookie_file(text)` = 0600 temp file for yt-dlp/gallery-dl, deleted after the run (yt-dlp's write-back is discarded); `load_jar(text)` for `requests`; `summarize(text)` -> `CookieJarSummary` (count, domains, Instagram `sessionid` + expiry; never a value), `CookieFileError` for anything not Netscape cookies.txt. `download_all(urls, cookies=...)` in all three modules; `download(url, ..., cookiefile)`. `OFM_COOKIES_FILE` is only read by alembic b1c2d3e4f5a7 (moved to the password admin's own cookies; file kept).

## Known limitation: server-side fetches of user links (review #37, 2026-10-25)
Every downloader fetches what a signed-in (admin-invited) user pastes, from the web/worker containers on the `internal` Docker network (postgres, redis, pot-provider reachable). There is NO egress guard for non-global addresses in this layer (yt-dlp, gallery-dl, the KVS reader's `requests`), while `web/reel_thumbs.kept_thumb` fetches only from public hosts (every resolved address global, each redirect re-checked). /download-media is the widest: any URL, Generic on, gallery-dl, KVS reader, raw errors in its card title. /clone-links narrows only its own path: Check takes an allowlist of single-post extractors, and `single_post` (preview read + worker download) drops Generic, so a redirector/shortener can no longer chain into an arbitrary host. A real fix = one shared guard here (resolve the host, refuse non-`is_global` addresses, re-check after redirects) applied to every path, /download-media first.

Callers: `web/routers/downloads/media.py` (the Download tool), `videos.py`/`images.py` (old jobs' routes only), `web/clone_links/preview.py` (`video_info`), `web/clone_links/run.py` (`downloaded(..., single=True)`).
