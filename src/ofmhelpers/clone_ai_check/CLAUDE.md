# clone_ai_check

Is a generated reel too glitchy to post? `check_clone(video, *, mirrored=False) -> CloneAiCheck`. Pure service: no DB, no web (callers save it: `web/stores/clone_ai_checks.py`, every field a column).

- `check.py` — the whole video as one contact sheet (`llm.frames.contact_sheet`: a still every `OFM_CLONE_AI_CHECK_EVERY_S` (1 s), first and last frame included, 2..`OFM_CLONE_AI_CHECK_MAX_FRAMES` (16), each `OFM_CLONE_AI_CHECK_FRAME_PX` (360) wide and labelled with its time), `RULES` as the system prompt, sent along `settings.llm.video_chain`: `LLM_DEFAULT_VIDEO` (Gemini 3.6-flash: user decision 2026-10-25, 3.8-flash was 503-overloaded for 10+ min while 3.6 answered), then each of `LLM_FALLBACK_VIDEO` (Gemini 3.8-flash, 3.5-flash, 3.5-flash-lite); every key of `GEMINI_API_KEY` (comma-separated) on a model before the next model when a key is out of quota (429) or rejected; an overloaded model (503) goes straight to the next model while the one before is down / rate limited / out of quota / not set up; any other failure (wrong shape after its re-ask, refused, wrong key, rejected input) is the answer. User decision 2026-10-25: a contact sheet of the whole video, not the raw video; GOOD or GLITCHY + a percent.
  - **Never Groq/Cerebras** (review #8/#59): an entry whose provider class reads no video (`MediaKind.VIDEO not in llm_class(...).media`) is skipped with a warning -- they get the sheet shrunk to 1024 px and Groq's qwen said GOOD to every dev reel (llm/CLAUDE.md findings). A chain of only such entries = "setup" error, reel to TRIAL.
  - **Deadline** (review #7): `OFM_CLONE_AI_CHECK_DEADLINE_S` (600 s, from the check's start) goes to `answered(..., deadline=)` (no retry or wait past it, llm/base.py) and no next model is asked once it passed -> "AI check took too long". Must stay below `OFM_CLONE_LINKS_REVIEW_TIMEOUT_S` (1200) minus one request (`OFM_LLM_TIMEOUT_S` 300) and the upload (unit test on the defaults). No cap it was ~6300 s worst case.
  - **Mirrored** (review #66): `mirrored=True` (the export flipped it) adds one sentence to `prompt_text`: text and logos reading backwards are not a glitch.
  - **No verdict** (never raised): `error` = a few fixed words safe on a page (`UNREADABLE`, `NO_SHEET`, `TOO_LONG`, `NO_ANSWER` "No AI model answered", `NO_MODEL`, or per class of a model's own failure: broken answer / refused / key rejected / could not take it / failed); `error_kind` = `quota` (any model out of quota or down, the deadline), `setup` (no key, unknown/retired model id, wrong key, nothing can read video), `failed` (anything else, an unreadable video); `error_detail` = every chain entry's `<entry>: <ErrorClass>: <message>` + provider detail, one per line (raw: the row and logs only, never a page); `provider`/`model` = the last one asked, `llm_s` = the time the chain took. Logs: a `not set up` hop and a `quota`/`setup` check at ERROR (Logfire `level >= 17`: the check is off for every reel until someone acts or the quota resets), an unavailable hop at warning. No re-check after a quota reset (user decision: no Check again, the VA sorts in Drive).
  - `unanswered(video, error, kind, *, detail=)` — the same no-verdict check for a caller whose check could not run at all.
  - The sheet lives in a temp dir for the call only; `stills_at` + `frame_px` redraw it (`sheet_at`).
- `models.py` — `CloneAiVerdict` (what the model must answer, its JSON schema goes with the prompt; field order = writing order: `reasoning`, `glitches` [`at_s`, `what`, `severity` minor|blocking], `glitch_percent` 0-100 = how sure it is unpostable). GOOD/GLITCHY is not asked (Groq kept leaving it out): `CloneAiVerdict.verdict(glitchy_percent)` = GLITCHY when any glitch is blocking OR `glitch_percent >= OFM_CLONE_AI_CHECK_GLITCHY_PERCENT` (50): several minor glitches can add up, and when the percent and the severities disagree the reel goes where a person looks first (review #30; `RULES` tells the model the percent is its whole judgement). No `min_length` on `reasoning` (a re-ask would spend free quota for a "Clean." answer). `CloneAiCheck` = the whole check as kept: verdict, glitches, reasoning, provider, model, prompt system + text, raw answer, attempts, sheet/LLM seconds, `input_tokens`/`thinking_tokens`/`output_tokens` (copied from `Answered`; None = the provider did not say), `error`/`error_kind`/`error_detail`.
- Debugging (user rule 2026-10-25: DB + Logfire, never report files): every check is a `clone_ai_checks` row (alembic a2b3c4d5e6f7); /clone-links' reviews also log one span `AI check {job_id}` (verdict, glitch_percent, folder, provider, model, check_error).

Callers: /clone-links (`web/clone_links/review.py`).
